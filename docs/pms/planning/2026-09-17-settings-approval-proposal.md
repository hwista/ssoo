# 프로젝트 사용 설정 — 승인-13 적용안

> 작성: 2026-09-17 · 상태: 조사·승인안 준비 완료, 제품 미변경 · 기존 승인-13 범위

## 확인한 현재 상태

프로젝트 설정 주소로 직접 접속하고 로그인한 뒤 새로고침해도 개인 프로필·계정 설정이 열린다. 1366·390 폭의 실제 브라우저에서 재확인했다. 별도 프로젝트 설정 구현에는 네 옵션과 브라우저 저장 코드가 있지만, 업무 화면·알림 처리에서 해당 값을 읽는 연결은 **0/4**다. 이는 프로젝트 전체 완성도가 아니라 이 네 설정의 반영 여부다.

| 항목 | 현재 구현과 누락 |
|---|---|
| 설정 진입 | 공용 개인 설정의 이전 주소 해석이 먼저 실행된다. 별도 프로젝트 설정 분기가 실제 직접 진입에서 선택되지 않음 |
| 완료된 작업 표시 | 값은 저장하지만 작업 탭은 전체 작업을 표시함. 표시·숨김 연결 없음 |
| 기본 프로젝트 보기 | 별도 설정에는 보드·목록·타임라인 선택이 있음. 내 프로젝트는 현재 카드 배치 하나이며 보기 선택 연결 없음 |
| 작업 배정 알림 | 서버에 담당자 필드와 변경 요청은 있으나 작업 생성·수정 흐름의 수신 알림 생성 없음. 현재 작업 화면은 담당자 이름을 표시하지만 지정 컨트롤 없음 |
| 이슈 변경 알림 | 정식 프로젝트 이슈 생성·변경 흐름에서 이 옵션에 따른 수신 알림 생성 없음. 보고서 승인 알림은 별도 기존 기능 |
| 저장 범위 | 네 옵션은 계정 구분 없는 브라우저 저장 키 하나를 사용. 사용자별 서버 저장·다른 기기 동기화 연결 없음 |

문서의 기존 “설정 직접 진입 연결” 설명은 경로 존재와 소스 검증에 관한 과거 기록이다. 실제 프로젝트 옵션이 작동한다는 근거로 쓰지 않는다. 브라우저에서 현재 연결되지 않은 설정 화면을 임의로 노출하거나 제품 코드를 바꿔 검증한 것은 아니다.

## 권장하는 적용 범위 — 승인 필요

설정 화면뿐 아니라 네 옵션이 실제로 동작하는 범위까지 같은 승인 항목에서 처리한다.

| 화면·기능 | 승인받을 변경 | 적용 경계 |
|---|---|---|
| 설정 진입 | 프로젝트 서비스 사용자 메뉴에 **프로젝트 사용 설정**을 추가. 기존 **개인 설정**과 별도로 열기 | 기존 개인 설정과 기존 설정 주소는 보존. 새 전용 주소·탭·직접 진입·새로고침·로그인 복귀 연결 |
| 완료된 작업 표시 | 프로젝트 상세의 작업 목록에서 완료 작업을 표시하거나 숨기기. 현재 숨긴 건수와 다시 표시하는 조작 제공 | 목록 표시만 변경. 완료 데이터·진척·공수 합계·공수 기록·마일스톤은 그대로 유지. 취소 작업까지 함께 숨기지 않음 |
| 기본 프로젝트 보기 | 적용 대상을 **내 프로젝트**로 명시. 보드(현재 카드 배치), 목록(표), 타임라인(일정) 중 선택 | 현재 카드 배치는 보존하고 목록·일정 보기를 추가. 같은 권한·같은 조회 범위·같은 프로젝트를 표시. 설정 변경은 해당 화면에 반영하고 다시 열 때 복원 |
| 작업 담당자와 배정 알림 | 작업 등록·담당자 영역에서 실제 프로젝트 멤버를 지정. 새 담당자에게 배정 알림 생성 | 기존 작업 관리 권한 적용. 생성 시 배정·담당자 변경 때만 새 담당자에게 전달. 미지정·동일 값 재저장·자기 자신이 수행한 배정은 알림 없음. 비활성/권한 없는 신규 지정 차단 |
| 이슈 변경 알림 | 정식 프로젝트 이슈의 상태·우선순위·기한·담당자·내용 변경을 담당자와 등록자에게 알림 | 중복 수신자·자신의 변경 알림 제외. 정렬·메모 등 관리용 값만 바뀌거나 실제 값이 같으면 생성하지 않음. 기존 정리용 이슈·보고서 승인 알림은 그대로 유지 |
| 계정별 설정 | 로그인한 사용자별로 서버에 저장하고 다른 기기에서도 같은 설정 적용 | 저장 성공을 확인한 뒤 완료 표시. 저장 실패는 재시도 가능하게 표시하고 미저장을 성공으로 표시하지 않음. 다른 계정에 값이 섞이지 않도록 처리 |

### 초기값과 기존 데이터

- 새 설정을 아직 저장하지 않은 사용자는 현재 업무 화면을 유지한다: 완료 작업 **표시**, 내 프로젝트 **보드(현재 카드 배치)**. 연결되지 않은 기존 설정의 `완료 작업 숨김` 초기값을 그대로 적용해 기존 항목을 갑자기 감추지 않는다.
- 두 새 업무 알림은 기본 **켜짐**을 제안한다. 끄면 해당 사용자의 이후 해당 종류 알림 생성을 중단한다. 이미 받은 알림·다른 종류의 알림은 지우지 않으며, 다시 켰을 때 과거 변경을 한꺼번에 보내지 않는다.
- 이전 브라우저 저장값은 소유자를 확인할 수 없으므로 특정 계정에 자동 이관하지 않는다. 기존 값은 삭제하지 않고, 새 설정에서 본인 선택을 저장하도록 한다.
- 타임라인은 각 프로젝트의 현재 단계에 저장된 예정 시작·종료일을 사용한다. 기간이 없거나 불완전하면 **일정 미정/기간 확인 필요**로 별도 표시하고 임의 날짜를 만들지 않는다. 일정에서 날짜를 끌어 바꾸는 기능은 추가하지 않는다.
- 기존 담당자 정보는 유지하고 표시한다. 새 지정은 활성 프로젝트 멤버로 제한하며, 권한·사용자 상태를 서버에서 다시 확인한다.

## 변경 영향과 보존 대상

변경 영향은 프로젝트 사용 설정의 진입·저장, 내 프로젝트 보기, 프로젝트 작업 표시·담당자 지정, 해당 두 종류의 업무 알림이다. 새로운 사용자별 설정 저장 계약과 필요한 업무 알림 생성을 추가한다. 기존 요청/응답을 제거하거나 필수 입력을 임의로 늘리지 않는다.

기존 개인 프로필·비밀번호 변경, 고객관리 계약·승인·청구, 문서관리 화면·저장·연동·권한, 다른 서비스의 알림 표시·읽음 처리 및 프로젝트 보고서/결재 알림은 보존한다. 기존 작업의 공수 입력·집계·계획 연결·상태 변경·삭제 조작을 보기 개선 과정에서 없애지 않는다.

화면·사용 방식·실제 알림 수신이 달라지므로 사용자가 앞서 정한 사전 승인 원칙을 적용한다. 승인안 제시 이후 사용자가 “진행하자”로 전체 범위를 승인했다. 2026-09-17 현재 승인 범위 구현과 검증을 진행 중이며, 아래 준비 시점 수치는 완료 검증 전 기준이다. 기존 승인-13을 세분 설명하는 것이며 새 승인 번호를 추가하지 않는다.

## 승인 후 실행 순서와 완료 기준

1. 사용자별 저장·권한·실패 처리와 별도 설정 진입을 연결한다. 개인 설정 경로와 다른 계정 전환을 먼저 검증한다.
2. 완료 작업 표시와 내 프로젝트 세 보기를 연결한다. 같은 데이터/권한, 날짜 누락, 빈 목록, 큰 데이터 범위, 큰 화면·휴대폰, 새로고침을 확인한다.
3. 담당자 선택·실제 배정 알림·정식 이슈 변경 알림과 수신 설정을 연결한다. 실제 서로 다른 계정, 설정 켜기/끄기, 자기 변경·중복/무변경·동시 요청·재시도, 비활성 계정·프로젝트 권한 회수, 기존 알림 보존을 확인한다. 중복 알림과 업무 저장 실패/알림 누락이 혼동되지 않도록 저장 경계를 검증한다.
4. 기존 작업·공수·문서 업무 회귀, 관련 서버 검사와 다섯 웹 빌드, 문서관리 필수 가드, 실제 브라우저 검증 후 전체를 완료 판정한다. 저장 또는 화면 노출만으로 승인-13을 완료 집계하지 않는다.

본 문서는 승인된 실행 범위다. 2026-09-17 구현·검증을 완료하여 네 옵션 실제 반영은 **4/4**다. 서버 15/15·실제 요청 21/21·실제 브라우저와 기존 업무 회귀, 서버/다섯 웹 빌드·문서관리 가드를 통과했다. 전체 승인 대장은 **20완료·2잔여**, 운영 증거는 **0/5**다. [최종 핸드오프](../../common/explanation/architecture/2026-09-17-project-settings-handoff.md)를 따른다. 아래 최초 관찰 증거는 준비 단계 기록이다.
