# 전문가 검색

> 2026-09-15 · 승인-02 구현 및 검증 기록은 최신 출시 핸드오프를 따른다.

## 화면 동작

이름·표시 이름·소개·보유 기술 이름으로 검색어를 입력한 뒤 Enter를 누른다. 처음에는 기존 검색 시작 안내를 표시한다. 여섯 분류는 조회 조건이며 분류를 바꾸면 첫 페이지부터 다시 조회한다. 빈 검색어에서 전체 분류를 선택하면 시작 안내로 돌아간다.

| 화면 분류 | 실제 기술 분류 |
|---|---|
| 전체 | 기술 분류 제한 없음 |
| 프로그래밍 | language |
| 프레임워크 | framework |
| 인프라 | infra, database |
| 관리 | management |
| 설계 | architecture, design |

결과에는 실제 사용자 사진(없으면 이름 기본 표시)·이름·제공되는 부서 정보·활성 보유 기술을 보여준다. 이름을 누르면 기존 공용 프로필로 이동한다. 결과는 20명씩 표시하며 이전/다음으로 이동한다. 조회 중·결과 없음·실패 후 재시도·권한 거절은 각각 구분한다. 검색어와 분류는 해당 화면의 상태이며 새로고침·주소 공유 복원 기능을 추가한 것은 아니다.

## 조회 및 보존 계약

- 기존 `GET /sns/skills/search`와 `GET /sns/skills`를 소비한다. 기존 검색 프로필 필드와 `userSkills`는 유지하고 `userName`, `displayName`, `avatarUrl`, `departmentCode`를 더한다.
- `keyword`는 이름/표시 이름/소개/기술 이름 중 하나와 일치하면 된다. `skillIds`가 있으면 활성 보유 기술 조건과 교집합으로 조회한다. 대소문자를 구분하지 않는다.
- 분류 선택은 활성 기술 목록의 실제 ID 배열로 전달한다. 단일 ID도 배열로 정규화한다. 잘못된 숫자 ID와 페이지는 입력 검증에서 거절한다.
- 페이지 번호·크기·전체 건수는 기존 `meta.page`, `meta.limit`, `meta.total`을 사용하고 프로필 ID 순서로 조회한다. 응답에 없는 전체 페이지 수는 화면에서 계산한다.
- 사용자/프로필 및 보유 관계/기술 원본이 모두 활성인 자료만 검색한다. 별도의 비공개 프로필 설정이 구현돼 있다는 의미는 아니다.
- 열람 권한은 기존 `canReadFeed`와 서버 기능 가드를 유지한다. 검색 캐시와 페이지 상태는 사용자별로 구분하며 사용자 전환 때 기존 앱의 캐시 초기화를 따른다.
- DMS, 공용 프로필, 게시판·게시물 및 통합 검색의 제품 구현은 변경하지 않는다.

## 후속 공용 프로필 정합성

검색 완료 당시 별도로 발견한 비활성 프로필·기술 표시는 사용자 승인-19로 후속 처리했다. 직접 조회와 내 프로필도 활성 상태를 적용하며, 재조회가 거절되면 이전 내용을 비운다. [공용 프로필 기준](../../../common/explanation/architecture/profile-active-state.md)과 [후속 핸드오프](../../../common/explanation/architecture/2026-09-15-profile-state-handoff.md)를 따른다.
