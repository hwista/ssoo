2026-09-17 갱신: 사용자가 1단계 공유를 승인했고 [구현·검증을 완료했다](../../common/explanation/architecture/2026-09-17-post-sharing-handoff.md). 아래 현재 상태와 미구현 기록은 9월 16일 승인안 작성 당시 사실이다. 링크·이미지 첨부는 여전히 후속 승인·구현 대상이다.

작성 당시 작업은 기존 승인-05의 구현 범위 구체화다. 세 버튼의 미연결을 새 승인 항목으로 늘리지 않는다. 승인안 작성은 기능 구현 완료가 아니며, 세 동작 모두 미구현으로 유지한다. 사용자 “좋아 진행하자”는 직전 제안한 공유·첨부 승인 범위 정리의 진행 지시로 적용했다. 화면·사용 방법 변경 전 승인 원칙에 따라 제품 변경은 실행하지 않았다.

## 현재 확인한 상태

| 기능 | 실제 구현 | 아직 필요한 부분 |
|---|---|---|
| 공유 | 게시물 카드에 공유 버튼이 있음 | 클릭 처리, 복사 결과 안내, 공유받은 게시물 하나를 여는 화면 |
| 이미지 첨부 | 작성창 아이콘과 데이터 구조의 게시물 첨부 관계가 있음 | 파일 선택·검사·미리보기·저장·글과 연결·권한 있는 이미지 조회·실패 정리 |
| 링크 첨부 | 작성창 아이콘이 있음. 글 본문은 일반 글자로 출력 | 주소 입력·검사·삽입과 실제 링크 열기. 별도 링크 미리보기 저장 기능은 없음 |

첨부 관계가 데이터 구조에 있다는 사실은 업로드 기능 완성을 뜻하지 않는다. 기존 게시물 단건 조회와 프런트 조회 도구는 있지만 이를 소비하는 게시물 상세 화면은 없다. 게시판 상세는 해당 게시판의 글 목록으로, 공유된 글 한 건의 목적지가 아니다. 기존 단건 응답은 피드 카드에 필요한 작성자·본인 반응 정보를 모두 제공하지 않는다.

## 먼저 승인받을 1단계: 공유와 게시물 보기

| 화면·상황 | 제안하는 동작 |
|---|---|
| 기존 게시물의 공유 버튼 | 기존 위치에서 누르면 작은 `게시물 공유` 창을 연다. 해당 글 주소, `링크 복사`, `닫기`를 표시한다 |
| 복사 성공 | `링크를 복사했습니다.` 안내. 글과 댓글·작성 중 입력은 유지한다 |
| 복사 실패 | `자동으로 복사하지 못했습니다. 아래 링크를 직접 복사해 주세요.` 안내와 선택 가능한 읽기 전용 주소를 유지한다 |
| 공유 주소 열기 | 기존 커뮤니티 틀 안의 `게시물` 탭에서 해당 글을 연다. 기존 카드의 작성자·본문·공개 범위·좋아요·북마크·댓글 열기/작성 방식을 재사용한다 |
| 로그인 전 접속 | 기존 로그인 화면을 거쳐 원래 게시물로 복귀한다. 로그인 전에는 글 내용이나 작성자 정보를 내보내지 않는다 |
| 삭제·없는 글·열람 불가 | `게시물을 볼 수 없습니다.` 안내와 `피드로 이동`을 제공한다. 비공개 글의 존재·내용을 구분해서 드러내지 않는다 |
| 통신 실패 | `게시물을 불러오지 못했습니다.`와 `다시 시도`를 제공한다. 권한 거절을 통신 실패로 바꾸지 않는다 |
| 여러 글·새로고침·계정 전환 | 글마다 탭과 주소를 일치시킨다. 새로고침은 같은 글을 복원하고, 계정 전환·재조회 거절 때 이전 계정의 내용을 남기지 않는다 |

공유는 주소를 전달하는 기능이다. 전체 공개를 포함한 기존 로그인·열람 조건을 유지하며, 링크 소지만으로 열람 권한을 부여하지 않는다. 외부 서비스로 자동 전송하거나 새 공개 열람 기능을 추가하는 제안이 아니다. 기존 글 작성·게시판·검색·프로필 동선을 변경할 권한으로 확대하지 않는다.

### 연동 변경 제안과 보존 범위

구현 검토용 제안은 커뮤니티에 `/post/:id` 진입과 해당 글의 피드 카드용 조회 `GET /sns/feed/posts/:id`를 추가하는 것이다. 새 조회는 기존 기능 권한 및 게시물 공개 범위 판단을 재사용하고, 기존 피드 항목과 같은 작성자·활성 댓글 수·현재 사용자의 좋아요/북마크 정보를 반환한다. 기존 게시물 단건·목록·작성 응답의 형식을 바꾸지 않는다. 현재 단건 조회에는 조회 수 증가 부수 효과가 있으므로, 새 카드 조회는 조회 수를 바꾸지 않는 읽기 전용으로 제안한다.

기존 공용 화면 구성요소를 사용하고 커뮤니티 내부에서 연결한다. 문서관리 화면·업무·연동 계약 및 다른 서비스의 사용 방식은 보존한다. 구현 중 이 범위 밖의 공용 동작 변경이 필요하다고 확인되면 구체적인 변경안을 같은 승인 대장에 먼저 정리한다.

### 승인 후 실행·검증 순서

1. 현재 소스의 권한·카드 응답을 기준으로 새 단건 조회와 거절 검사를 구현한다. 없는 글, 비활성 글, 조직·팔로워·나만 보기 범위를 실제 계정으로 검증한다.
2. 게시물 보기와 주소·탭·로그인 복귀를 연결한다. 첫 피드에 없는 오래된 글도 주소로 직접 조회할 수 있어야 한다.
3. 공유 창과 복사 성공·실패·수동 복사를 연결한다. 키보드 열기·닫기, 초점 복귀와 작성 중 입력 보존을 확인한다.
4. 새 서버·커뮤니티 빌드에서 1440×1000, 1366×768, 390×844의 표시·직접 접속·새로고침·뒤로 가기·다중 탭·댓글·반응을 확인한다. 복사 결과는 실제 복사값으로 검증하고, 권한 실패와 통신 실패는 별도 시나리오로 확인한다.
5. 관련 요청·콘솔 오류, 계정 전환·접근 철회 후 이전 내용 잔존, 기존 게시판·글 작성·댓글·고객관리/문서관리 업무를 확인한다. 수정 후 검증을 반복하고 동일 에이전트의 구조·불필요 변경 검토임을 명시한다.

1단계만 끝나면 `공유 완료 / 첨부 미완료`로 기록한다. 승인-05 전체는 아래 첨부 두 동작까지 승인·구현·검증하기 전 완료 처리하지 않는다.

## 후속 단계: 같은 승인-05에서 별도 확인할 내용

| 순서 | 제안 범위 | 구현 직전 확정할 사항 |
|---|---|---|
| 2. 링크 첨부 | 기존 아이콘에서 주소 입력 → 일반 웹 주소 검사 → 작성 본문에 삽입 → 게시 후 클릭 가능한 주소 표시. 외부 사이트 제목·이미지를 자동 수집하는 미리보기는 포함하지 않는 초안 | 본문 주소 삽입 방식과 기존 글의 주소도 링크로 표시할지 확정. 작성 취소·실패 시 입력 보존, 잘못된 주소·실행 가능한 주소 거절과 새 창 열기 검증 |
| 3. 이미지 첨부 | 기존 아이콘에서 선택 → 미리보기·개별 제거 → 글과 함께 게시 → 글 안에서 조회. 초안 제한은 사진 4장, 장당 5MB, JPEG·PNG·WebP | 수량·크기·형식은 기존 계약이 아닌 제안값. 이미지 배치·원본 열기·본문 없는 사진 글 허용 여부·업로드 실패 복구를 화면안과 함께 확정 |

이미지는 저장 위치·소유자·임시 업로드와 게시물 연결·취소 및 실패 파일 정리·동일 파일 재시도·이미지 실제 형식 검사가 함께 필요하다. 파일 바이트 조회도 글과 동일한 로그인·열람 권한을 검사하고 글 삭제·권한 변경 때 접근을 재평가해야 한다. 문서관리의 비공개 저장 주소를 공개하거나 해당 업무 계약을 바꾸지 않는다. 이 표는 다음 승인 자료이며, 1단계 승인에 첨부 구현을 묶어 해석하지 않는다.

## 2026-09-17 첨부 두 기능 통합 승인안

승인 갱신: 사용자가 위 통합 승인안에 **“진행”**으로 승인했다. 링크 → 이미지 저장·권한 → 이미지 화면 → 회귀 검증 순서로 완료했다. 아래의 “아직 승인된 동작이나 구현 결과가 아니다”는 승인안 작성 시점의 기록이며, 완료 여부는 최종 검증 결과로 별도 판정한다.

현재 상태는 **공유 완료 / 링크 첨부 미착수 / 이미지 첨부 미착수**다. 첨부는 구현 실패로 막힌 것이 아니라 공유 단계의 승인 범위 밖이어서 아직 구현하지 않은 작업이다. 동작하지 않는 버튼은 출시 전 해결할 기능 공백이며, 승인 대기라는 이유로 출시 허용 상태로 간주하지 않는다.

사용자 “그럼 진행하는게 맞지?”에 따라 남은 두 기능의 실행안을 함께 구체화했다. 아래는 기존 승인-05의 후속 제안이며 **아직 승인된 동작이나 구현 결과가 아니다**. 승인 번호와 완료 수를 늘리지 않는다. 앞의 후속 단계 초안에서 열어 둔 선택지는 이 안으로 제안한다.

### 화면과 사용 방식

| 화면·동작 | 승인 요청 내용 |
|---|---|
| 링크 첨부 | 기존 링크 아이콘 → `링크 첨부` 창 → `웹 주소` 입력 → `추가`. 정상 주소를 작성 본문 끝에 새 줄로 삽입한다. 별도 제목 입력이나 외부 사이트 미리보기 수집은 추가하지 않는다 |
| 링크 검사·취소 | `http://` 또는 `https://`로 시작하는 유효한 주소만 받는다. 빈값·잘못된 주소·다른 방식의 주소는 입력창 안에서 안내한다. 취소·닫기는 기존 본문과 공개 범위를 보존한다 |
| 게시된 링크 | 새 글과 기존 글의 본문에 있는 정상 웹 주소를 클릭 가능한 링크로 표시하고 새 탭에서 연다. 본문 저장값·줄바꿈은 보존한다. 주소가 아닌 글자는 그대로 표시하며 코드나 서식을 실행하지 않는다. 적용 화면은 기존 게시물 카드를 사용하는 피드·게시판·공유 게시물이다 |
| 이미지 선택 | 기존 이미지 아이콘으로 사진 선택. 한 글에 최대 4장, 장당 5MB(5,000,000바이트), JPEG·PNG·WebP를 허용한다. 잘못된 선택은 이유를 안내하고 기존 본문과 이미 선택한 사진은 유지한다 |
| 게시 전 미리보기 | 본문 아래에 선택 순서대로 작은 미리보기와 사진별 `제거`를 제공한다. 추가 선택과 개별 제거를 지원한다. 파일 선택창 취소는 이미 작성한 내용을 유지한다 |
| 이미지 게시 | 현재처럼 본문 입력을 필수로 유지한다. 사진만 있는 글은 이번 범위에 포함하지 않는다. 게시 중에는 진행 안내와 중복 제출 방지를 제공한다. 모두 저장·연결된 뒤에만 성공 처리하고 작성창을 비운다 |
| 게시 실패·재시도 | 같은 작성창에서 본문·공개 범위·선택 사진을 유지하며 재시도를 제공한다. 응답 유실 후 재시도도 글이나 첨부 중복 생성으로 이어지지 않아야 한다. 사진 일부만 저장된 상태를 성공으로 표시하지 않는다 |
| 게시된 이미지 | 본문 아래에서 1장은 카드 폭에 맞춰 표시하고, 2~4장은 2열로 선택 순서대로 표시한다. 미리보기는 사진 전체가 보이도록 비율을 유지한다. 사진을 누르면 같은 서비스의 확대 창에서 전체 이미지를 보고 닫는다 |
| 이미지 불러오기 실패 | 해당 이미지 위치에 `이미지를 불러오지 못했습니다.`와 `다시 시도`를 표시한다. 게시물 자체의 열람 권한이 없으면 기존 게시물 접근 불가 상태를 따른다 |
| 작성 취소·이동 | 작성창의 기존 `취소`는 본문·공개 범위와 선택 사진을 함께 초기화한다. 기존 열린 탭 사이 이동에서는 초안을 유지한다. 새로고침 후 초안 복원이나 자동 저장은 이번에 추가하지 않는다. 로그아웃·계정 변경 시 이전 계정의 사진 초안을 남기지 않는다 |

### 저장·권한 및 연동 범위

- 커뮤니티 첨부 저장·조회와 작성 연동을 추가한다. 기존 텍스트 작성 요청은 계속 유효해야 하며 기존 필드를 삭제하거나 의미를 바꾸지 않는다. 첨부 추가 요청·응답은 구현 후 생성하는 연동 문서에 반영한다.
- 이미지 실제 데이터도 게시물과 동일한 로그인·열람 조건으로 조회한다. 전체 공개도 현재의 로그인 조건을 유지한다. 파일 주소를 안다는 이유로 권한을 우회할 수 없어야 한다.
- 파일명과 선언된 형식만 신뢰하지 않고 실제 이미지 형식·크기·개수를 서버에서 확인한다. 다른 사용자의 파일 연결을 거절한다. 문서관리의 저장 주소나 연동 계약을 사용·변경하지 않는다.
- 게시물 삭제·접근 철회 이후 새 이미지 요청을 거절하고 계정 전환 때 이전 이미지 표시를 정리한다. 이미 사용자가 내려받은 사본을 회수하는 기능으로 설명하지 않는다.
- 취소·저장 실패·중단으로 남는 임시 파일을 정리하고, 실패 후 재시도가 기존 글이나 다른 사용자의 파일을 삭제하지 않도록 검증한다. 저장 경로·영속 보관·재시작 후 조회도 검증한다. 운영 배포와 실제 운영 저장소 설정은 기존 운영 출시 항목에서 별도로 확인한다.
- 문서관리와 다른 서비스의 화면·사용 방법·연동 계약은 보존한다. 구현 중 이 범위 밖 변경이 필요하면 같은 승인 대장에 구체적인 변경 내용을 제시한다.

### 승인 후 순서와 완료 기준

1. **링크 첨부 구현·검증**: 주소 입력·검사·본문 삽입·취소·게시 실패 입력 보존, 기존/새 글 링크 열기, 키보드·초점 복귀를 확인한다.
2. **이미지 저장·권한 구현·검증**: 실제 파일 저장·재조회, 제한 위반·형식 위장·소유권·조직/팔로워/나만 보기·삭제/철회·재시도 중복·실패 정리를 확인한다.
3. **이미지 화면 연결·브라우저 검증**: 선택·미리보기·개별 제거·본문과 게시·확대·실패 재시도·탭 이동·계정 전환을 실제 브라우저에서 수행한다. 서버 실패와 응답 유실도 별도 재현한다.
4. **기존 기능 회귀·문서 갱신**: 새 빌드에서 1440×1000, 1366×768, 390×844를 확인하고 기존 공유·댓글·반응·글 작성 및 고객관리·문서관리 핵심 업무를 재검증한다. 실패는 수정 후 다시 검증하고 증거와 실제 완료 범위를 기록한다.

링크와 이미지의 정상·실패·권한 검증까지 끝나야 승인-05 전체를 완료 처리한다. 지금은 문서 구체화만 수행했으며 제품 소스 변경·첨부 동작 검증·완료 수 증가는 없다.

## 이번 확인의 증거와 한계

- 직접 읽은 소스: 커뮤니티 작성창·게시물 카드·본문 경로·탭 경로·게시물 조회 도구 및 요청 형식, 서버 게시물·피드·접근 정책, 첨부 데이터 구조. 소스상 공유/첨부 클릭 처리와 첨부 저장·조회 연결이 없음을 확인했다.
- 기존 승인-22 실행 환경의 커뮤니티에서 이미지/링크 버튼을 1440·390 너비로 눌렀다. 4개 조합 모두 새 입력·선택창·파일 입력·내용 변경 없음, 작성 초안 보존, 커뮤니티 변경 요청 0건을 확인했다. 이는 **미구현 재현 4/4**이며 기능 통과 수가 아니다.
- 현재 격리 피드가 비어 있어 이번에는 실제 공유 버튼 클릭을 재검증하지 않았다. 공유의 기존 브라우저 감사와 이번 소스 확인을 구분한다. 테스트 글을 생성하거나 기존 글의 조회 수를 올리지 않았다.
- 최초 캡처는 검증용 글꼴 설정 누락으로 한글 표시가 불완전했다. 원본을 보존하고 해당 설정을 적용한 별도 브라우저에서 네 조합을 다시 확인했다. 최종 캡처는 `compose-font-*`, 최종 동작 기록은 `browser-inspection-font.log`다. 관련 요청·콘솔·실행 오류는 0건이며 전체 화면 품질 검수로 확대하지 않는다.
- 사전 검사, 규칙 동기화, 문서 산출물 검사 및 문서 구조 검사 281개가 통과했다. 새 공유·첨부 기능의 동작 검증은 승인 후 구현할 작업이다.
- 새 제품 빌드는 하지 않았다. 이번 산출물은 승인안과 증거이며 기존 실행 산출물을 재사용한 관찰이다. 사전 검사·규칙 동기화·문서 검사 결과 및 소스/웹 산출물 보존 비교는 [검증 묶음](../../../output/playwright/approval05-share-attachments-20260916/)에 기록한다.
- [직전 구현 핸드오프](../../common/explanation/architecture/2026-09-16-token-replay-handoff.md)의 완료 수와 실제 운영 미완료 판정은 유지한다. 이 승인안으로 전체 출시 가능을 선언하지 않는다.
