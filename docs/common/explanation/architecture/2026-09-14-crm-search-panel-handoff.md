# 고객관리 검색 결과 가림 개선 결과

> 후속 최신: [네 서비스 검색 가림 개선](2026-09-14-service-search-panel-handoff.md)에서 승인-17 완료·승인-18 분리와 총 8완료·10대기를 확인한다. 아래는 승인-16 당시 기록이다.

> 2026-09-14 · 승인-16 완료 · 총 17항목 중 7완료·10승인 대기

작업공간이 좁을 때 사용 팁·검색 기록이 결과를 가리던 문제를 고객관리 검색에서 해결했다. 처음에는 결과를 보여주고, 기존 버튼으로 보조 영역을 다시 열고 닫을 수 있다. 사용자 “좋아 다음 진행하자”로 승인받은 구체 제안을 적용했다.

## 화면별 결과

| 화면·동작 | 확인 결과 |
|---|---|
| 작은 화면·공간이 부족한 화면 | 보조 영역이 기본으로 접혀 검색 결과와 빈 안내가 바로 보인다 |
| 공간이 충분한 큰 화면 | 기존처럼 검색 결과와 보조 영역이 나란히 표시된다 |
| 패널 펼치기·접기 | 기존 사용 팁·검색 기록과 버튼을 유지한다. 사용자가 펼치면 기존 겹침 방식으로 열리고 다시 접을 수 있다 |
| 직접 접속·새로고침·검색어 변경 | 검색 화면이 복원되며 좁은 작업공간의 결과가 기본 패널에 가려지지 않는다 |
| 상단 검색·필터·크기 전환 | 기존 검색을 유지하고, 넓은 화면↔작은 화면 반복 전환 뒤에도 결과와 패널 조작이 정상이다 |
| 문서관리·운영관리·프로젝트·커뮤니티 | 기존 검색 패널 동작과 열기/닫기를 보존했다. 이 네 서비스의 작은 검색 화면에서도 같은 가림을 확인했지만 이번 적용 대상은 아니다 |

화면 전체 너비에 새로운 기준을 만들지 않고 기존 작업공간 크기 판단을 사용한다. 1920px에서는 나란히 배치되고, 1440px는 좌측 메뉴 등을 제외한 공간이 부족해 390px와 함께 기본 접힘을 확인했다. 사용자가 직접 펼친 패널까지 강제로 닫아 사용을 막는 동작은 도입하지 않았다.

## 검증 결과

- **다섯 서비스 새 빌드 완료**: 의존 작업 포함 9/9, 캐시 재사용 0. 문서관리 보존 검사와 별도 새 빌드도 통과했다.
- **고객관리 회귀 7항목 통과**: 새 패널 1건, 기존 검색 2건, 탭 한도 2건, 입력·저장 2건. 첫 묶음은 6통과·1실패였고, 마지막 작은 화면 탭 검사는 반복 로그인 요청 제한으로 업무 화면에 진입하지 못했다. 실패를 보존하고 다른 로그인 검사 종료 후 해당 1건을 재실행해 통과했다. 제한값과 제품은 변경하지 않았다.
- **문서관리 관련 회귀 3/3**: 검색 권한·승인·거절·권한 철회, 새로고침·댓글, 내부/외부 문서 연결을 격리된 자료로 검증했다. 문서관리 전체 검수 재완료라는 뜻은 아니다.
- **직접 브라우저**: 고객관리 1920·1440·390px에서 결과·빈 검색어·검색 결과 없음·패널 조작·필터·새로고침을 확인하고, 넓은 화면↔작은 화면 3회 왕복을 통과했다. 실제 결과 제목 좌표가 패널에 가려지지 않는지도 검사했다. 로그인 이후 정상 검색 흐름의 요청·콘솔·실행 오류 0, 고객관리 직접 검증의 업무 저장 요청 0.
- **다른 서비스 보존 비교 8상태**: 네 서비스 각각 1920·390px의 기존 기본값과 패널 열기/닫기가 유지됐다. 좁은 화면의 기존 가림은 해결로 집계하지 않는다.
- 사전 검사·타입·코드·규칙·문서 검사 및 최종 작업본/실행물 대조를 확인한다. [최종 실행 결과](../../../../output/playwright/approval16-search-panel-20260914/results.md)에 검사별 증거를 기록한다.

## 변경과 보존 경계

제품 변경은 세 곳이다. 기존 공용 검색 두 계층에 좁은 화면 동작 선택값을 전달하고 고객관리만 기존 접기 방식을 선택했다. 공용 기본값·작업공간 측정·패널 상태·열기/닫기 코드는 보존했다. 새로운 상태·화면 복제·의존성은 없다. 검색어·필터·서버·권한·저장 계약, 문서관리와 다른 앱의 제품 소스는 이번에 변경하지 않았다.

구조·불필요 변경 검토는 동일 에이전트가 수행했으며 독립 검토자 승인으로 표시하지 않는다. 빌드 이후 제품·검사 소스 변경은 없다. 최종 문서 갱신과 다섯 실행물 지문은 [작업본 대조](../../../../output/playwright/approval16-search-panel-20260914/final-reconciliation.json)로 구분한다. 기존 사용자 수정과 이전 승인 결과를 보존했다.

검증은 기존 격리 서버와 전용 자료를 사용했다. 웹 앱만 새 빌드로 재시작했으며 실제 운영 배포는 하지 않았다. 기존 로그인 전 세션 거절 응답은 승인-09로 유지한다. 최초 반복 로그인 제한 실패는 검증 속도 문제이며 은폐하거나 성공으로 재분류하지 않는다. 검색 기록 등 브라우저 상태와 실제 운영 자료를 구분한다.
