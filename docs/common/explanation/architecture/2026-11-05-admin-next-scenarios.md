# Admin 공통 운영의 다음 시나리오 검토

> 기준일: 2026-11-05 · 상태: 코드 기반 후속 검토, 아래 신규 시나리오의 실제 실행 합격은 아님

사용자는 SMTP·임베딩·Microsoft 실제 연동을 예산 확보 후로 보류하고 다음 검토로 진행하도록 지시했다. 보류 항목과 재개 방법은 [외부 연동 안내](../../guides/deferred-external-integrations.md), 기존 17개 프로그램·15개 시나리오의 증거는 [구현 대장](2026-11-04-admin-program-implementation.md)에 둔다. 이 문서는 외부 연동 성공을 가정하지 않는다.

## 다음 검증 순서

| 순서 | 운영 상황 | 재사용할 프로그램 | 현재 코드·증거와 추가 확인 |
|---|---|---|---|
| AC16 | 운영자가 편집창을 열어 놓은 동안 다른 관리자가 운영 권한을 회수한 뒤, 이전 창에서 저장 | ADM-02/07/10/16 및 변경 대상 프로그램 | 소속·이용권·역할 변경은 트랜잭션 안에서 관리자 권한을 재확인한다. 기존 관리자 교체 API에서 회수 후 접근 거절을 확인했지만, 열린 입력창의 저장 거절·입력 보존·재조회 동선은 별도 실제 검증 필요 |
| AC17 | 예약 소속 시작 또는 이용권·위임 만료 시각을 로그인한 상태로 통과 | ADM-03/06/10/11/16 | 소속과 이용권의 현재 효력·만료 이유 계산 및 종료 시각 exclusive 규칙 존재. 기존 변경/회수 검증과 구분해 경계 직전·직후의 조회/직접 API·5앱 접근을 확인 |
| AC18 | 조직 폐쇄·퇴사 처리 중 일부 단계 후 통신이 끊겨 다른 담당자가 이어 처리 | ADM-01/02/03/04/06/11/16 | 영향 조회·관계별 상태·변경 사유·감사와 단일 관계 명령은 존재. 여러 프로그램의 순차 작업 전체가 한 트랜잭션은 아니므로 재접속 후 완료/미완료 식별·중복 처리 거절·남은 작업 재개를 확인 |

세 시나리오 모두 기존 관리 대상과 화면을 사용한다. 부족한 동작을 재현했을 때 해당 원본 프로그램을 보완한다. 시나리오별 메뉴·통합 대시보드·새로운 데이터 사본을 만들지 않는다. 앱 도메인의 업무 소유권 이전은 계속 각 앱의 책임이다.

## 첫 번째 AC16의 실행 명세

1. 기존 최종 관리자는 유지하고, 검증용 후임 운영자와 검증 대상 조직·사용자만 준비한다.
2. 후임 운영자가 소속/이용권 또는 역할 편집창을 열고 변경 사유를 입력한다.
3. 별도 관리자 세션에서 후임의 관리 권한을 회수한다.
4. 후임의 열린 화면에서 저장한다. 기존 토큰을 사용한 직접 API도 확인한다.
5. 저장은 거절되고 대상 관계는 바뀌지 않아야 한다. 실패 안내와 재조회/복귀 동선이 보여야 하며, 허용하지 않은 화면 전환이나 입력 손실 여부를 확인한다.
6. 최종 관리자로 이력과 원본을 비교하고 검증 자료만 종료한다. 조회 실패와 실제 저장 성공을 혼동하지 않는다.

통과 증거는 권한 회수 전후 응답, 열린 화면의 실제 클릭·오류 안내·복구, 대상 DB 상태 및 변경 이력이다. 코드에 검사문이 있다는 사실만으로 통과 처리하지 않는다. 지금 단계에서는 이 명세를 다음 실제 검증 대상으로 선정했으며 실행 결과를 기록한 것은 아니다.
