# 커뮤니티 링크·이미지 첨부 처리 결과

> 2026-09-17 · 승인-05 공유·링크·이미지 완료 · 총 22항목 중 18완료·4잔여

사용자가 링크·이미지 첨부 통합 승인안에 “진행”으로 승인하여 두 기능을 구현했다. 앞서 완료한 공유와 함께 같은 승인-05에서 관리한다. 공유·링크·이미지 세 기능의 구현·검증을 마쳐 승인-05 전체를 완료 처리했다. 실제 운영 배포는 실행하지 않았다.

| 기능·화면 | 확인한 결과 |
|---|---|
| 링크 첨부 | 주소 입력·검사·본문 끝 삽입·취소·초점 복귀. 기존 글과 새 글의 주소 열기 및 실제 새 탭 이동 확인 |
| 게시판 링크 | 요약에서 긴 주소가 잘려 보여도 원래 전체 주소로 이동. 일반 글자·줄바꿈·스크립트처럼 생긴 본문은 문자열로 유지 |
| 사진 선택 | 기존 아이콘에서 파일 선택, 4장 제한, 잘못된 추가 선택 시 기존 입력 유지, 미리보기·개별 제거·작성 취소 확인 |
| 사진 게시·확대 | 본문과 JPEG·PNG·WebP 사진을 함께 저장, 순서대로 표시, 확대 창과 새로고침 후 조회. 한글 파일명 보존 |
| 실패 복구 | 게시 실패와 이미지 조회 실패의 안내·입력 보존·재시도. 실제 서버 저장 후 응답만 유실시킨 두 크기의 브라우저 검사에서 같은 글로 복구 |
| 탭·계정·권한 | 큰/작은 화면 탭 이동 중 사진 초안 유지. 계정 전환 후 비공개 글·사진 제거, 실제 계정의 조직·팔로워·나만 보기 및 파일 데이터 접근 거절 |
| 기존 기능 | 실제 공유 복사값, 댓글 등록·좋아요·북마크 요청, 기존 텍스트 글 작성·실패 재시도. 고객관리 2/2·문서관리 4/4 회귀 통과 |

## 검증과 한계

관련 서버 검사 **44/44**, 실제 첨부 요청 검사 **41/41**, 저장 실패·정리·재시작 재시도 검사 **4/4**를 수행했다. 서버와 커뮤니티 새 빌드, 세 크기(1440×1000, 1366×768, 390×844), 큰/작은 화면의 추가 실패·초안 보존 검사와 실제 요청·콘솔·실행 오류 수집을 포함한다. 정상 흐름의 관련 오류는 0이며 고의 실패·권한 거절은 따로 분류한다.

권한 철회 검사는 브라우저 복귀 이벤트를 주입하여 실제 재조회 및 이전 글·사진 제거를 확인했다. 운영체제의 자연스러운 창 전환 자체를 검증한 증거는 아니다. 외부 링크 새 탭 이동은 외부 서버에 의존하지 않도록 목적지 응답만 검증 도구에서 제공했다. 사용자가 이미 별도로 저장한 사진 사본을 회수하는 기능은 아니다.

이미지 처리기는 워크스페이스에서 이미 고정한 버전을 서버에 연결했다. 운영 의존성 감사에서 알려진 취약점 0건, 실제 이미지 처리기 실행 검사를 통과했다. 연동 문서의 **462개 요청 목록**은 실행 서버와 일치한다.

[검증 묶음](../../../../output/playwright/approval05-attachments-20260917/)에는 실행 스크립트, 로그, 화면, 실패 보완 기록과 최종 지문·자료 정리 결과를 모은다. [현재 첨부 동작](../../../sns/explanation/architecture/post-attachments.md)과 [승인안](../../../sns/planning/2026-09-16-share-attachments-proposal.md)이 상세 기준이다.

## 보존 범위와 검토

제품 소스 변경은 커뮤니티 화면·서버 커뮤니티에 한정한다. 기존 텍스트 게시 요청은 유지하고 사진과 본문을 함께 게시하는 별도 요청과 권한 있는 사진 조회를 추가했다. 목록·피드의 첨부 메타데이터는 추가 필드이며 파일 저장 경로는 반환하지 않는다. 공용 화면 패키지, 문서관리 및 다른 서비스의 제품 소스·기존 연동 계약을 변경하지 않았다.

구조 검토와 불필요 변경 검토는 같은 에이전트가 수행했다. 기존 작성 트랜잭션·공개 범위 정책·인증 요청 도구·화면 원자를 재사용했다. 선택 직후의 임시 업로드, 별도 첨부 데이터 구조, 외부 사이트 미리보기 수집, 사진 전용 글, 자동 초안 저장은 추가하지 않았다. 독립 에이전트 검토로 표기하지 않는다.

저장 시도별 파일 경로를 분리하여 제한 시간을 넘긴 이전 요청의 실패 정리가 나중에 성공한 재시도의 파일을 삭제하지 않도록 보완하고 해당 회귀 검사를 추가했다. 실패 및 중단으로 남은 미연결 파일은 정리 대상이며 다른 글의 연결된 파일을 지우지 않는다.

## 보완·검증 실패 기록

한글 multipart 파일명 깨짐과 게시판의 긴 링크 목적지 잘림을 보완했다. 파일 검사 타입과 데이터베이스 확장 트랜잭션 타입을 실제 실행 계약에 맞췄다. 문자 검사 린트도 보완했다.

검증 도구의 파일 전송 재실행이 바이트를 누락한 실패는 일반 업로드와 구분했고, 실제 요청을 유지하는 응답 단계 차단으로 교체했다. 이어서 도구 환경의 인코딩 함수, 사전 요청 구분, 유지된 숨김 탭, 모바일에 없는 헤더 검색/작성 버튼 및 파일 선택창 처리를 보완했다. 계정 전환 검사에서는 다른 공개 글 사진까지 세던 조건을 해당 비공개 글과 실제 거절 화면 기준으로 바로잡았으며 비공개 본문은 전체 문서에도 남지 않음을 확인했다.

서버 준비 전 접속과 로그인 검사 중첩으로 발생한 429는 통과로 숨기지 않았다. 기동 완료를 기다리고 로그인 검사를 순차 실행했으며 기존 로그인 제한을 완화하지 않았다. 초기 오프라인 의존성 정보가 오래되어 실패한 설치는 승인된 온라인 설치로 수행했다.

검증용 게시물·계정·조직·첨부와 해당 검색 색인 작업을 정리하고 업무 데이터 개수가 시작 전과 같은 것을 확인했다. 검증용 사진 폴더도 제거했다. 다른 네 웹 앱의 실행 산출물 지문은 시작 전과 동일하며 공용 패키지·다른 서비스 제품 소스 변경은 0이다.

## 남은 출시 작업

첨부 기능의 운영 저장 경로·영속 보관·백업/복구는 기존 실제 운영 출시 항목에 포함한다. 새 승인 번호로 분리하지 않는다. 실제 운영 증거 **0/5**는 그대로 미확보이며 로컬 기능 검증을 운영 출시 완료로 표기하지 않는다.

**승인 항목 18/22 완료·4잔여**다. 신규 승인 번호 0, 전체 완료 항목 +1이다. 이 수치는 제품 전체 구현률이나 운영 출시 준비율이 아니다.

다른 잔여 항목은 계약 승인 기록의 업무 의미, 프로젝트 설정의 실제 반영, 문서 다이어그램 표현, 실제 운영 출시 환경이다. 이번 기능 완료 여부와 전체 출시 준비 판정을 구분한다.
