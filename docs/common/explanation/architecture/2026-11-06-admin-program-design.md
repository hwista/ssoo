# Admin 프로그램별 사용성 설계

> 상태: 설계 확정·구현·인수 검증 완료 · 범위: 공통 관리 17개 · 실행: web-ralplan → web-ralph

## 목적과 변경 경계

각 프로그램이 맡은 데이터와 처리를 이해하고 끝낼 수 있게 한다. 프로그램 수를 줄이거나 사용자/조직 상세에 다른 프로그램의 편집 기능을 모으지 않는다. 공용 recipe·메뉴·주소·인증·서버 권한 계약은 유지한다. DB 스키마와 유료 연결은 변경하지 않는다.

사용자 지시는 화면별 적합한 설계, 설계 검토·보완, 구현, 실제 브라우저 처리와 회귀 검증까지 포함한다. 사용자/조직의 기존 중첩 처리 패널은 담당 프로그램으로 이동하는 동선으로 대체한다. 기능 자체는 해당 프로그램에서 보존한다.

## 설계 원칙

1. 제목/경로/안내/작업의 공용 틀은 유지한다. 본문은 데이터의 계층·관계·기간·판정·처리 상태에 맞춘다.
2. 관련 화면은 사용자 ID·조직 ID·앱·이력 분류/대상 ID를 URL로 전달한다. 이름은 표시용으로만 사용하며 판정/저장 키는 ID다. 대상 조건은 화면에 표시하고 해제할 수 있다. 직접 주소·새로고침·기존 탭 재사용에서도 동일해야 한다.
3. 다른 프로그램의 입력 폼을 중첩하지 않는다. 현재 대상의 관계 요약과 담당 화면 연결만 제공한다. 자기 프로그램의 편집/상세는 기존 Dialog/second-grid를 사용할 수 있다.
4. 상태 변경은 처리 대상·기간·효과·사유를 확인하고 실행한다. 실제 성공 응답과 재조회로 완료를 판단한다. 날짜 오류, 저장 실패, 충돌에서 입력을 보존한다.
5. 데이터가 적거나 많은 경우와 모바일 390×844를 함께 검증한다. 집계는 서버 범위를 과장하지 않고 현재 조회 범위를 명시한다.

## 화면별 설계와 구현 범위

| ID / 주소 | 소유 데이터·처리 | 적합한 본문과 입력 | 관련 프로그램 연결 / 보존 |
| --- | --- | --- | --- |
| P01 `/organizations` | 회사·조직 기본정보, 상하 관계, 활성 상태 | 계층 경로가 보이는 조직 목록; 조직명/코드 검색; 선택 조직 아래에 하위 조직 추가; 수정 시 자기 자신/하위 조직을 부모로 선택하지 않음 | 관계 상세는 하위 조직·소속·이용권·위임·권한 영향 요약. 각 처리는 조직 ID를 전달해 소속/이용권/권한/이력 프로그램으로 이동 |
| P02 `/users` | 사용자 식별·기본정보·등록·수정 | 이름·로그인 ID·역할·참여 상태 중심 명부와 기본정보 폼. 계정 복구는 연결 버튼으로 계정 프로그램에 위임 | 소속/이용권/예외/이력은 사용자 문맥을 가진 연결 선택. 중첩 관리 표와 편집을 제거 |
| P03 `/memberships` | 사용자↔조직 관계, 주 소속·겸직, 기간, 이동·종료 | 관계 목록과 사용자/조직 문맥; 검색 가능한 대상 선택; 배치·변경·이동·종료별 입력; 기간 역전 즉시 설명; 직책 코드의 입력 의미 명시 | 조직 이동의 회수 효과 보존. 완료 후 같은 사용자 이용권/진단으로 이동. 종료 기록 재배치는 기존 날짜를 복사하지 않음 |
| P04 `/accounts` | 계정 상태·로그인·잠금·세션·복구 | 계정 식별·이메일·최근 로그인·상태 중심 목록과 계정 운영 상세. 사용자 등록/기본정보 편집은 사용자 관리로 연결 | 복구/잠금 해제/세션 회수의 기존 확인·권한·실패 안내 보존. 선택 계정 직접 진입 유지 |
| P05 `/applications` | 5앱 기준·공통 책임·접속 경로(조회) | 5개 앱 비교 목록 유지. 업무 앱별 이용권 조회 연결 제공; 배포 설정에서 관리되는 기준임을 안내 | 앱별 도메인 설정을 편집하지 않음. 이용권 화면에 serviceCode 전달 |
| P06 `/service-grants` | 사용자·조직별 앱 역할·기간·회수 | 사용자/조직/앱 문맥 관계 목록. 부여 폼은 대상→앱/역할→종료일→사유. 만료된 재부여는 종료일 수정 필요를 명시하고 과거 날짜 제출 방지 | 같은 사용자의 소속 관리/접근 진단/해당 기록 이력으로 이동. 기존 회수 및 다른 이용권에 의한 접근 유지 안내 보존 |
| P07 `/roles` | 역할별 기능 권한 집합 | 역할 선택→기능별 체크→추가/제거 차이→영향 사용자→사유→저장. 수정 중 역할 전환은 입력 폐기를 확인 | 기능 명세 조회 보존. 조직/사용자 예외 편집은 해당 프로그램 소유 |
| P08 `/organization-permissions` | 조직에 직접 적용하는 공통 권한·기간 | 조직 조건과 권한/기간 목록. 편집 시 직접 적용 범위와 상속되지 않음을 안내; 기간 검증 | 조직 ID 조건 진입과 해제. 조직의 구성원 처리는 소속 프로그램, 전후 값은 이력 프로그램 |
| P09 `/user-permissions` | 사용자 공통 허용·차단 예외·만료 | 대상과 허용/차단 효과를 함께 표시; 회수/재부여 시 다른 허용 경로가 살아날 수 있음을 안내; 만료 검증 | 사용자 ID 조건 진입과 해제. 기존 상세 예외 조회 보존, 최종 효과는 진단으로 연결 |
| P10 `/access-diagnosis` | 이용 자격·기능 권한의 조회/판정 근거 | 대상 선택→계정/소속 요약→5앱 판정→상세 근거. 편집 동작을 내장하지 않음 | 사유에 맞는 계정/소속/이용권/예외 프로그램으로 대상 유지 이동. 세부 자료 권한 조회와 원본 식별자 보존 |
| P11 `/approval-authorities` | 승인 담당자·조직/앱 범위·최대 역할·기간 | 범위별 위임 목록과 적격 후보 검색 유지. 저장 전 담당자·조직·앱·최대 역할·기간 요약, 만료 입력 검증 | 신청 처리·변경 이력으로 연결. 조직 전체/특정 조직의 의미와 자기 승인 금지 보존 |
| P12 `/approvals` | 신청의 승인·반려 결정 | 신청 카드에서 신청 대상·사유·요청 상태·처리 결과 확인. 처리 영역에 결정할 효과와 역할/사유 표시, 처리 중 입력/버튼 중복 방지 | 가입 신청과 조직/서비스 신청의 기존 구분 유지. 대기 없음과 조회 실패 구분, 완료 내역 확인 |
| P13 `/operation-history` | 공통 변경 사건과 전후 값(조회) | 조건 목록→선택 사건의 비교 패널. 변경 항목만/전체 항목 전환, 필드명·대상 이름 우선, 원본 식별자 보존 | 모든 이력 버튼은 category/subjectId/userId/organizationId를 전달해 이 프로그램으로 이동; 관련 관리 프로그램 연결 유지 |
| P14 `/codes` | 공통코드 그룹의 값·표시명·순서·상태 | 그룹 선택→코드 목록→그룹이 명확한 편집 폼. 순서의 숫자 유효성, 사용처·삭제 영향 확인 | 기존 source-compatible 진입·읽기/소유 경계와 참조 상세 보존. 앱 도메인 코드 관리 흡수 금지 |

| P16 `/email-operations` | 메일 전달 현황·개별 기록·재시도·연결 | 발송 현황/전송 기록/연결 설정을 화면 내 명확한 작업 선택으로 구분. 기존 세 영역 내용은 유지, 한 번에 선택한 업무를 집중 표시 | 로컬 보관·외부 전달 차이 보존. 발송은 전용 로컬 시험 수신함만; 외부 제공자 설정 변경/발송 금지 |
| P17 `/ai-operations` | 작업 대기열·실패·재시도·연결 준비·색인 대상 | 대기열/개별 작업/연결 준비/색인 대상의 작업 선택. 선택한 작업의 원인·재시도 가능 여부·후속 작업 번호 확인 | 전체 작업 실행을 시험용으로 누르지 않음. 전용 작업의 재등록과 로컬 실행 가능 범위만 검증; 유료 연결 변경 금지 |

## 실행 순서와 설계 검토

- 기준선: 현재 소스 보존, 기존 3000번 실행 이미지/포트 확인, 변경 전 17개 브라우저 상태 기록.
- 설계 검토 1: 프로그램별 데이터·처리 소유자를 대조한다. 사용자/조직/진단의 중첩 편집을 제거하되 원래 기능은 담당 프로그램에서 접근 가능해야 한다.
- 설계 검토 2: URL 조건이 전달만 되고 실제 조회/입력에 적용되지 않는 경우를 실패로 정의한다. 이름만 넘기거나 검색 문자열만으로 특정 사용자를 지정하지 않는다.
- 구현 A: 프로그램 문맥 이동, 관계 요약, 이력 이동. B: 각 소유 화면의 계층/기간/차이/정책/작업 선택. C: 오류·충돌·실제 처리 검증과 보완.
- 구조 검토: 공용 shell은 변경하지 않는 것을 기본으로 한다. 실제 이력 검증에서 상세 패널의 퍼센트 높이가 부모를 넘는 결함을 확인해, 공용 second panel의 높이 기준과 내부 스크롤만 수정했다. Admin 내 업무 조합은 Admin이 소유한다. 검색 원자는 기존 SsooSearchInput을 사용하고 새 입력은 inventory에 등록한다.
- 정리 검토: 미사용 중첩 패널 import와 임시 기능을 정리한다. 기능 삭제가 아니라 책임 이동인지 모든 기존 진입과 대조한다.
- 최종 통과는 [테스트 명세](2026-11-06-admin-program-test-spec.md)의 P01~P17과 공통 회귀 증거를 요구한다. 미실행·실패·외부 의존 항목을 통과로 표시하지 않는다.

## 배포와 복구

관리형 Docker 명령으로 기존 Admin 3000번만 갱신한다. 포트·서버를 추가하지 않는다. 기존 저장 공간 정책의 보호/정리를 유지한다. 소스 원복은 이번 변경만 대상으로 하며 사용자 변경을 덮어쓰지 않는다. UI 작업에서 DB 스키마는 변경하지 않는다. 실제 시험은 전용 fixture와 변경 전 snapshot을 사용하고 LIFO 정리 결과를 검증한다.
