# 공용 프로필 상태 반영 작업 결과

> 2026-09-15 · 승인-19 완료 · 총 20항목 중 11완료·9승인 대기

> 후속 2026-09-16: 승인-20 표시 갱신도 완료했다. 현재 12완료·8대기는 [최신 핸드오프](2026-09-16-profile-refresh-handoff.md)를 따른다. 아래 수치와 신규 발견은 승인-19 당시 기록이다.

사용자 ‘좋아 다음 진행하자’로 직전 비활성 프로필 처리안을 승인받았다. 서버가 비활성 프로필을 반환하던 문제와, 실제 재조회에서 찾을 수 없음 응답을 받아도 이전 프로필이 남던 문제를 처리했다.

| 기능·화면 | 확인 결과 |
|---|---|
| 비활성 프로필 직접 조회·내 프로필 | 기존 찾을 수 없음 응답과 다시 시도 안내, 조회로 재활성화·재생성하지 않음 |
| 소개의 보유 기술 | 기술 원본과 보유 관계가 모두 활성인 항목만 표시 |
| 비활성 프로필 수정·경력 추가 | 데이터 쓰기 전에 거절, 이름 변경을 포함해 실패 요청이 자료를 수정하지 않음 |
| 이미 열린 프로필의 재조회 거절 | 이전 내용·편집값·게시물 표시 제거, 다시 시도 후 정상 조회 복구 |
| 일시적인 서버 오류 | 기존 프로필 표시 유지, 정상 재조회 후 오류 안내 해제 |
| 정상 프로필 | 응답 필드·소개·기술·경력 조회, 소개 편집·저장·재조회와 팔로우 저장/해제 확인. 빠른 변경 뒤 표시 잔존은 아래 승인-20으로 분리 |
| 다섯 서비스 | 큰/작은 화면 직접 접속·새로고침·재시도와 프로필 비활성/활성 계정 전환 후 내 프로필 확인 |
| 기존 업무 | 고객관리 입력·저장·확정 잠금 2/2, 문서관리 기존 업무 4/4 통과 |

프로필만 비활성인 정상 계정으로 내 프로필 거절을 검사했다. 계정 자체가 비활성인 경우는 서버의 실제 요청 검사로 별도 확인했다. 커뮤니티에서는 전문가 검색에서 기존 공용 프로필로 이동하고 비활성 대상은 검색에서 빠지는 것을 확인했다. 나머지 서비스에 전문가 검색 진입 기능을 새로 구현하거나 해당 흐름을 검증했다고 표시하지 않는다.

## 검증과 승인 경계

서버 관련 검사 15/15, 실제 요청·격리 데이터 검사 8/8을 통과했다. 브라우저 17실행 묶음은 다섯 서비스의 두 크기 및 재조회, 두 종류 계정의 본인 프로필, 커뮤니티 검색·오류 복구·정상 저장 보존을 포함한다. 이 수치를 서로 합산해 기능 완료율로 표시하지 않는다. 실제 비활성 응답 검사와 실패 복구를 위한 주입 응답 검사를 구분했다. 예상 거절/주입 오류 외 최종 해당 검사 오류는 없었다.

공용 화면 수정 때문에 다섯 서비스를 새로 빌드했다. 문서관리 검증·빌드, 다른 네 웹 앱 빌드(의존 작업 포함 8/8·캐시 0), 서버 빌드(3/3·캐시 0), 사전 검사·서버 lint·패턴·규칙/문서 검증을 수행했다. 검증용 자료는 원래 건수로 복원하고 문서 5건의 삭제 성공도 확인했다. 상세 로그·실패 원본·변경 및 빌드 대조는 [실행 증거](../../../../output/playwright/approval19-profile-state-20260915/results.md)를 따른다.

이번 제품 변경은 프로필 서버·관련 검사·공용 프로필 요청/실패 상태 처리에 한정한다. 기존 찾을 수 없음 안내와 오류 형식을 재사용했다. DMS 문서 업무의 화면·요청/응답, 별도 앱 배치·문구·권한·스키마·원본 자료 일괄 변경은 없다. [공용 프로필 기준](profile-active-state.md)에 조건과 한계를 기록했다. 구조·불필요 변경 검토는 같은 에이전트가 수행했으며 독립 검토자 승인으로 표시하지 않는다.

## 새로 발견해 남긴 문제

커뮤니티 공용 프로필에서 **진입 직후 팔로우 저장은 성공하지만 버튼·숫자가 이전 상태에 머무는 경우**를 재현했다. 새로고침하면 저장된 팔로우가 표시됐다. 기존 성공 조회 재사용 경로는 이번에 수정하지 않았으며 [승인-20 변경안](../../../../output/playwright/approval19-profile-state-20260915/approval20-proposal.md)으로 분리했다. 잠시 지난 뒤의 저장·해제 보존 검사가 통과한 것을 빠른 클릭 문제의 해결로 표시하지 않는다.

이번에는 **완료 +1·신규 +1**이다. 완료 **10→11건**, 총 항목 **19→20건**, 승인 대기 **9→9건**이다. 승인 처리 비율 **11/20(55.0%)**은 출시 준비율이 아니다. 다음은 승인-20의 변경 직후 표시 갱신을 먼저 처리하도록 제안한다. 기존 [게시판 생성 승인안](../../../../output/playwright/approval19-profile-state-20260915/approval03-proposal.md)도 준비돼 있으며 미적용 상태다.

검증은 격리 자료와 검증용 서비스에서 수행했다. 운영 배포와 실제 운영 증거 0/5는 남아 있으며 전체 출시 목표의 완료를 선언하지 않는다.
