# Admin 공통 관리 프로그램 목록과 시나리오 연결

> 기준일: 2026-11-04
> 상태: 최초 프로그램 구성 제안. 현재 구현은 구현 대장, 최신 메뉴 배치는 [2026-11-05 프로그램 배치](2026-11-05-admin-program-navigation.md)를 따른다. 아래 최초 진입 위치 제안과 최신 배치를 구별한다.
> 상위 범위: [Admin 플랫폼 공통 관리](2026-11-04-admin-common-management-scope.md)

## 1. 프로그램을 나누는 기준

프로그램은 **하나의 관리 대상 또는 운영 책임에 대해 조회하고 필요한 작업을 수행할 수 있는 기능 단위**로 정의한다. 목록·상세·등록·수정·상태 변경·대상 이력은 해당 프로그램 내부 기능이다. 메뉴, URL, 탭, 모달의 개수와 프로그램 수는 같지 않다.

예를 들어 사용자 소속 관리 프로그램은 조직 상세에서는 조직으로, 사용자 상세에서는 사용자로 필터링해서 연다. 같은 관계의 변경 로직과 편집 화면을 재사용한다. 전보·겸직·소속 종료는 이 프로그램이 수행하는 작업이다. 업무 시나리오별 전용 페이지를 만들지 않고 프로그램의 조합으로 처리한다.

관리 프로그램 후보 **17개**와 기존 초기 설정·본인 이용을 위한 보조 프로그램 **3개**를 식별했다. 관리 후보 중 조직 권한/사용자 예외의 쓰기 기능은 운영 정책 확정 후 범위를 정한다. 일반 역할·서비스·권한 항목을 임의로 생성할 수 있어야 한다는 가정은 두지 않는다.

`기존 확장`은 일부 화면/API가 있다는 뜻이며 아래 요구 기능 전체가 구현됐다는 뜻이 아니다. `신규 관리 기능`도 새 DB 테이블이 필요하다는 뜻은 아니다. 기존 관계 모델을 관리하는 화면/API가 부족한 경우를 포함한다.

## 2. 관리 프로그램 후보 17개

|---|---|---|---|---|
| ADM-01 | 회사·조직 관리 | 조직 목록·계층·상세, 등록·명칭/상위 조직 변경, 중지·복구, 구성원/이용권/위임 영향 조회 | 조직 관리의 기본 화면 | **기존 확장.** `/organizations` → 조직 API. 계층·기본 변경 존재. 관련 관계 조회와 중지 선행 작업 연결 보완 |
| ADM-02 | 사용자 관리 | 사용자 검색·상세, 계정 등록, 기본정보·기본 역할 변경, 참여/활성 상태 조회·변경 | 사용자 관리의 기본 화면 | **기존 확장.** `/users`. 소속·이용권·위임·계정 운영 프로그램을 같은 사용자 ID로 연결. 참여 상태 전환과 계정 활성 상태의 의미 정리 |
| ADM-03 | 사용자 소속 관리 | 사용자↔조직 관계 조회·배치, 주 소속·겸직·조직 내 직책·기간 변경, 이동·종료, 이력 | 조직 관리의 구성원, 사용자 상세의 소속에서 동일 프로그램 진입 | **신규 관리 기능.** `UserOrganizationRelation`과 승인 생성 로직은 존재. 운영자 일반 변경 API/UI 부족. 인사 부서 코드 편집과 구분 |
| ADM-04 | 계정 상태·복구 운영 | 로그인 계정·외부 인증 연결 상태·세션 조회, 이용 중지/재활성화, 세션 회수, 잠금 해제, 비밀번호 재설정 요청 | 사용자 상세의 계정 운영 | **기존 확장.** 사용자 운영 UI와 `/auth/admin/users/*`. 중지 동작은 ADM-02와 같은 명령을 사용. 지원하지 않는 MFA 초기화·외부 연결 해제를 동작 가능한 버튼으로 제시하지 않음 |
| ADM-05 | 애플리케이션 기준 조회 | 5앱의 식별자·이름·접속 경로·관리 책임과 이용 정책 조회 | 애플리케이션 이용 관리의 기준 탭/선택 목록 | **신규 조회 연결.** 분산된 앱/서비스 상수를 정합하게 표시. 고정 앱 목록을 사용하며 동적 앱 생성·URL 편집은 이번 기본 요구에 포함하지 않음. Admin 운영 권한과 4개 업무 앱 이용권 구분 |
| ADM-06 | 서비스 이용권 관리 | 사용자×조직×앱별 목록·상세, 부여·역할/기간 변경·회수·재부여, 유효/무효 사유·이력 | 애플리케이션 이용 관리, 사용자 상세의 이용권에서 동일 프로그램 진입 | **신규 관리 기능.** `ServiceGrant`, 신청 승인, 서버 회수 API 존재. 관리자 목록·변경·회수 UI 부족. 직접 부여 권한과 승인 경로의 정책 일치 필요 |
| ADM-07 | 역할·기능 권한 관리 | 역할 목록, 권한 기능 명세, 역할별 허용 기능 편집, 사용 중 사용자·영향 조회 | 역할 & 권한의 역할/권한 명세 | **기존 확장.** `/roles`의 역할 편집·catalog. 운영자가 편집할 역할/권한 범위를 명세. 역할 신규 생성은 고정 역할을 해석하는 코드 영향 검토 후 결정 |

| ADM-09 | 사용자 공통 권한 예외 관리 | 사용자별 허용/차단 예외 조회, 범위·기간·사유 지정, 부여·만료·회수·이력 | 역할 & 권한의 예외, 사용자 상세에서 연결 | **조회 기존/변경 조건부.** 현재 예외 조회 있음. 직접 예외 발급이 필요한지와 역할·조직 권한의 우선순위 확정. 도메인 객체 예외는 해당 앱 관리 기능으로 연결 |

### 프로그램별 기본 행위자

- ADM-01~11, ADM-13~17의 기본 운영자는 해당 기능 권한이 있는 플랫폼 관리자다. 조직 담당자의 직접 배치·이용권 발급 권한은 추가 정책을 명시한 경우에만 연다. 현재의 **승인 위임을 직접 관리 권한으로 확대 해석하지 않는다.**
- ADM-12는 요청 유형과 대상 범위에 맞는 관리자/위임 승인자만 처리한다. 본인은 자신의 신청 조회·취소·재신청 기능만 사용한다.
- ADM-08/09의 쓰기 기능을 채택하지 않으면 조회·원천 변경 경로를 명시하고 AC08의 허용 운영 범위를 그에 맞게 한정한다. 구현되지 않은 작업을 가능한 시나리오로 판정하지 않는다.

## 3. 기존 초기 설정·본인용 보조 프로그램

| ID | 프로그램 | 역할과 연결 | 현재 진입점 |
|---|---|---|---|
| AUX-01 | 최초 관리자 설정 | 운영 시작 전 최초 관리자 생성. 이후 교체·복구는 ADM-02/04/07에서 수행 | `/setup`, `/initial-setup` |
| AUX-02 | 본인 소속 조회·신청 | 본인의 승인 소속 조회, 소속/조직 생성 신청·취소·결과 확인. ADM-03 관계와 ADM-12 신청 기록 사용 | `/my-organizations` |
| AUX-03 | 본인 서비스 이용 조회·신청 | 본인 이용권 조회·신청·취소·결과 확인·앱 진입. ADM-06 이용권과 ADM-12 신청 기록 사용 | `/my-services` |

보조 프로그램의 실제 배치는 별도 화면 설계에서 결정한다. 기존 세 메뉴 중 `신청 승인`은 ADM-12에 해당하며, AUX-02/03의 화면을 관리자 소속·이용권 관리 프로그램과 혼동하지 않는다. 기존 로그인·비밀번호 재설정 등 공용 인증 화면은 이들 프로그램의 기반 기능이며 새 Admin 관리 프로그램으로 중복 집계하지 않는다.

## 4. 프로그램 사이의 연결 계약

| 기준 대상 | 연결할 프로그램 | 일관성 기준 |
|---|---|---|
| 사용자 ID | ADM-02 → ADM-03/04/06/09/10/11/12/16 | 선택한 사용자·필터·접근 범위를 전달. 상세마다 다른 사용자/소속 복제본을 저장하지 않음 |
| 조직 ID | ADM-01 → ADM-03/06/08/11/12/16 | 구성원·이용권·위임과 변경 영향 확인. 조직 중지에 필요한 선행 처리를 같은 ID로 이어감 |
| 앱 코드 | ADM-05 → ADM-06/10/11 | 고정 서비스 식별자와 정책의 의미 유지. 메뉴 표시와 API 접근 자격을 구별 |
| 신청 유형+신청 ID | ADM-12 → ADM-02/03/06 및 AUX-02/03 | 유형별 원본 식별자 보존. 가입 신청과 소속 신청의 ID 충돌 방지. 승인 결과로 바뀐 실제 관계를 연결 |
| 변경 대상+처리 식별자 | 모든 변경 프로그램 → ADM-16 | 변경자·범위·사유·결과·관련 신청 식별자를 추적 가능하게 설계 |

신청 승인과 직접 관리가 같은 관계를 바꿀 때 적용할 조건은 같아야 한다. 예를 들어 활성 사용자/조직 검사, 중복 소속·이용권 제약, 유효기간, 부여 가능한 역할 제한을 공통 변경 로직에서 적용한다. 승인이라는 경로만 특별히 검증을 우회하거나 별도 데이터에 기록하지 않는다.

직접 변경을 모든 운영자에게 허용한다는 뜻은 아니다. 신청이 필수인 행위는 요청 경로로 연결하고, 직접 변경이 허용된 행위만 프로그램에서 제공한다. 정책 결정은 다음 상세 명세 단계에서 고정한다.

## 5. 15개 공통 운영 시나리오의 프로그램 사용 순서

| 시나리오 | 행위자와 프로그램 순서 | 완료 확인 |
|---|---|---|
| AC01 최초 관리자/관리자 교체 | 최초: AUX-01. 교체: 관리자 ADM-02에서 후임 준비 → ADM-07/02에서 필요한 권한 배정 → 후임 로그인·ADM-10 확인 → 기존 관리자 권한 조정 | 후임 실제 접근과 마지막 관리자 보호, ADM-16 기록 |
| AC02 조직 신설·계층 변경 | 관리자 ADM-01 등록/변경 → 관련 코드가 필요할 때 ADM-13 참조 → ADM-16 확인 | 중복·계층 순환·부모 상태, 기존 ID와 참조 보존 |
| AC03 계정·소속 준비 | 관리자 ADM-02 등록 → 직접 배치 허용 시 ADM-03. 신청 경로는 본인 AUX-02 → 담당자 ADM-12 → ADM-03 결과 조회. 외부 가입 요청은 ADM-12의 가입 유형부터 처리 | 계정 생성만으로 소속·앱 이용권이 자동 부여되지 않음. 실제 관계와 신청 결과 일치 |
| AC04 전보·겸직·소속 종료 | 관리자 ADM-03에서 기존/신규 소속·기간·주 소속 처리 → ADM-06 이용권 검토·조정 → ADM-11 승인 위임 조정 → ADM-10/16 확인 | 이전 조직 접근과 새 조직 이용 자격, 기존 업무 이력 보존 |
| AC05 조직 폐쇄·복구 | 관리자 ADM-01 영향 조회 → ADM-03 구성원 처리 → ADM-06/11 이용권·위임 처리 → 필요 시 ADM-08 조직 권한 처리 → ADM-01 중지. 복구 시 같은 관계를 재검토 | 활성 하위 조직·미처리 관계가 남으면 이유·처리 경로 제공. 과거 업무 자료 이전은 해당 앱 책임 |
| AC06 이용권 부여·변경·회수 | 관리자 ADM-05 앱 기준 확인 → ADM-06에서 허용된 직접 처리. 신청 경로는 본인 AUX-03 → 담당자 ADM-12. 이후 ADM-10/16 확인 | 조직·앱·역할·기간이 정확하며 회수/만료 후 새 요청이 거부됨 |
| AC07 중지·퇴사·재활성화 | 긴급 중지: 관리자 ADM-04에서 계정 차단·세션 회수. 관계 종료 필요 시 ADM-03/06/11 및 채택한 ADM-08/09 검토. 복구: ADM-02/04와 각 관계 프로그램에서 정책에 따라 복원 → ADM-10 | 일시 중지와 관계 종료 구별. 재활성화 시 과거 권한이 어떻게 되살아나는지 명시·검증 |
| AC08 공통 권한 변경 | 관리자 ADM-07 역할 편집, 필요하고 채택된 경우 ADM-08/09 → ADM-10 유효 권한 → ADM-16 기록 | 범위 초과·자기 권한 상승 제한, 예외 우선순위·만료 확인 |
| AC09 승인자 교체 | 관리자 ADM-11 후임 지정/기존 위임 회수 → 후임 ADM-12 대기 건 확인·처리 → ADM-16 | 회수된 담당자 처리 차단, 후임의 범위와 최대 역할 적용 |
| AC10 반려·취소·재신청·경합 | 담당자 ADM-12 승인/반려, 본인 AUX-02/03 취소/재신청 → ADM-12 이력 및 ADM-03/06 결과 조회 | 오래된 화면·중복 결정·처리 중 대상 중지에도 관계가 중복/오발급되지 않음 |
| AC11 공통코드 변경 | 관리자 ADM-13 등록/변경/중지/복구 → 사용하는 공통 화면 재조회 → ADM-16 | 기존 표시·신규 선택·소유 범위·이력 확인 |
| AC12 인증·계정 복구 | 관리자 ADM-14 정책 확인/변경 → 필요 시 ADM-04 복구 요청 → ADM-15 실패 확인·재시도 → 본인 기존 공용 복구 화면 | 실제 전송 결과·사용자 복구·세션 처리까지 확인 |
| AC13 5앱 접근 반영 | 관리자 ADM-03/04/06/07에서 변경 → ADM-10 진단 → 해당 사용자로 5앱의 화면·직접 URL·API 검증 | 열린 세션·재조회·재로그인 시 실제 정책 일치. 진단 화면만으로 합격 판정하지 않음 |
| AC14 공통 변경 추적 | 관리자 ADM-16에서 사용자/조직/요청/변경자 기준 조회 → ADM-10 또는 대상 원본 프로그램 이동 | 원인·영향 범위·결과를 추적. 누락된 감사 대상은 보완 전 미완료 |
| AC15 공통 AI 실패·복구 | 관리자 ADM-17 준비 상태·실패/대기 확인 → 허용된 실행/재처리 → 결과 조회 | 작업 결과·중복 제한 확인. 개별 작업 식별·재시도 미지원이면 해당 기능 보완 필요 |

AC04/05/07 같은 여러 프로그램의 순차 작업은 현재 단일 트랜잭션으로 완료된다고 주장하지 않는다. 즉시 접근 차단이 필요한 경우 계정 중지나 해당 이용권 회수를 먼저 수행하고, 실패 시 현재 완료/미완료 관계를 재조회해 이어 처리할 수 있어야 한다. 전보의 원자적 소속 변경처럼 동일 관계 안에서 묶어야 하는 작업은 ADM-03의 서버 명령으로 설계한다.

위 표는 처리 경로 설계다. 정책 미정·UI/API 부족 항목이 남아 있으므로 15개 시나리오 실행 합격을 뜻하지 않는다.

## 6. 메뉴에 배치할 때의 제안

| 메뉴/진입 묶음 | 프로그램 배치 |
|---|---|
| 조직 관리 | ADM-01을 기본으로 ADM-03 구성원 관리, 권한·이용권·위임·이력 연결 |
| 사용자 관리 | ADM-02를 기본으로 ADM-03 소속, ADM-04 계정 운영, ADM-06 이용권, ADM-09/10/16 연결 |
| 애플리케이션 이용 관리 | ADM-05 앱 기준, ADM-06 조직/사용자별 이용권 |
| 역할 & 권한 | ADM-07 역할·기능 명세, ADM-08 조직 권한, ADM-09 예외, ADM-10 진단, ADM-11 승인 위임 |
| 신청 처리 | ADM-12 유형별 처리함. 현재 가입 신청 위치와 신청 승인 메뉴의 변경은 이후 UI 설계에서 확정 |
| 공통코드 | ADM-13 |
| 인증 정책 | ADM-14 설정, ADM-15 메일 운영 |
| 운영 이력 | ADM-16. 현재 역할 & 권한의 감사 탭에서 분리할지는 탐색성 검토 후 결정 |
| AI 운영 | ADM-17 |

대시보드는 요약과 대상 프로그램으로의 진입을 제공한다. 조직/사용자/권한 편집 기능을 대시보드에 다시 구현하지 않는다. 위 배치는 제안이며 기존 메뉴 삭제·흡수·이동을 실행한 기록이 아니다.

## 7. 구현 준비 순서와 공통 완료 기준

1. ADM-01/02/03/06의 식별자·상태·관계 종료·복구 규칙을 먼저 명세한다. 기존 기능에 부족한 관계 조회/변경을 채우는 것이 우선이다.
2. ADM-04/07/10/11/12를 연결해 직접 관리와 신청 승인의 조건을 일치시키고 계정 중지·담당자 회수·권한 반영을 검증한다. ADM-08/09 쓰기 기능은 정책 선택 결과에 맞춰 포함한다.
3. ADM-16의 감사 기록과 대상 이력 조회는 각 변경 프로그램 구현 시 함께 연결한다. 마지막에 이력 기록을 별도로 덧붙이지 않는다.
4. ADM-05/13/14/15/17은 현재 구현을 활용해 해당 시나리오의 부족한 조회·오류 복구·검증을 보완한다. 신규 일반화 기능은 요구가 있는 범위로 한정한다.

프로그램별 상세 설계에는 검색 조건·목록/상세 필드·처리 버튼·허용 행위자/데이터 범위·API·변경 모델·상태 전환·동시 변경 처리·오류/재시도·감사·검증 사례를 넣는다. 먼저 각 프로그램이 단독으로 동작하는지 확인하고 이후 위 사용 순서로 연결 검증한다.
