사용자는 2026-09-18 배포 서버·접속 주소·운영 설정 위치가 **미정**이라고 답했다. 이후 사용자는 첫 사용 범위로 **사내 직원만, 사내망 또는 회사 원격접속으로 사용**을 선택했다. 추가로 전체 사용자는 **최대 약 40명**, **사용 가능한 사내 서버 있음**을 확인했다. 사용자가 제공한 이미지에는 Rocky Linux 9.7, 처리장치 2, 메모리 4(단위 미표기), 운영체제 디스크 50GiB와 개발용 구분이 보인다. 사용자는 기억이 불확실하다고 했으므로 후보 사양으로만 기록한다. 현재 할당 자원·공용 여부·실제 주소·운영 설정 위치·운영 전환 가능 여부는 확인 전이다. 40명을 검증된 동시 처리 용량으로 해석하지 않는다. 승인-06 안에서 계속 관리하며 완료·신규 항목 수는 바꾸지 않는다.

현재 작업공간의 기본 운영 설정 파일은 없고, 별도 운영 설정·승인 법인정보 파일 위치도 실행 환경에 지정되지 않았다. 운영 호스트에 해당 파일이 없다는 뜻은 아니다. 실제 배포 대상과 보관 위치를 받아 확인해야 한다. 기존 법인정보 초안에는 예시값만 있고 승인되지 않았다.

## 배포 대상이 미정일 때의 결정 순서

| 결정 | 선택에 따라 달라지는 점 | 현재 |
|---|---|---|
| 첫 사용 범위 | 사내 직원만 사내망 또는 회사 원격접속으로 사용 | 사용자 1번 선택으로 확정 |
| 초기 규모 | 전체 사용자 최대 약 40명. 동시 활동 인원·문서 용량은 별도 확인·검증 | 사용자 규모 확정, 처리 용량 검증 전 |
| 운영 자원 | 기존 사내 서버의 할당 가능 자원·다른 업무와의 공용 여부·담당자·백업 저장소 확인 | 사내 서버 있음, 구체 조건 확인 요청 중 |

현재 저장소의 배포 정의는 데이터베이스·공용 서버·다섯 웹 서비스를 한 호스트의 컨테이너로 실행하는 형태다. 운영 구성은 데이터베이스 포트를 외부에 열지 않고 웹/서버도 호스트 내부에 연결하며, 암호화 접속과 외부 접근은 별도로 승인된 앞단 서버가 맡는다. 운영 문서·첨부 저장 경로와 별도 백업 경로도 필요하다. 이 구조가 실제 운영 부하를 수용한다거나 무중단 구성이 검증됐다는 뜻은 아니다.

기존 사내 서버에 현재 배포 구조를 적용하는 안을 기준으로 준비한다. 먼저 서버 운영체제와 컨테이너 실행 가능 여부, 실제 할당 가능한 자원·기존 업무 부하·회사 네트워크 접근 조건을 확인한다. 서버가 있다는 사실만으로 배포 적합성을 통과 처리하지 않는다. 서비스 분산, 외부 관리형 데이터베이스, 새 인증 방식으로의 전환은 현재 결정에 자동 포함하지 않는다. 필요성이 확인되면 기존 환경·동작에 대한 영향과 검증 계획을 제시한다.

## 서버 이미지에서 확인한 참고 사양

| 항목 | 이미지의 표기 | 해석·확인 필요 |
|---|---|---|
| 운영체제 | Rocky Linux 9.7 | 현재 서버에서 버전·구조·컨테이너 실행 환경 확인 필요 |
| 처리장치 | 2 | 할당 수치로 기록. 실제 논리 처리장치 수·경합 확인 전 |
| 메모리 | 4 | 단위가 없으므로 4GB로 읽는 것은 잠정 해석. 실제 총량·사용 가능량 확인 필요 |
| 운영체제 디스크 | 50GiB, 루트 경로 | 전체 문서 저장 용량이나 현재 여유 공간을 뜻하지 않음. 별도 데이터 디스크 존재 여부 미확인 |
| 서버 구분 | 개발 | 운영 전환 허용·기존 업무 영향·공용 여부 확인 필요 |

이미지의 계정·비밀번호는 문서·증거·실행 명령에 복사하지 않았으며 서버 접속에도 사용하지 않았다. 서버 주소도 실제 배포 대상으로 확정하지 않았다.

**현재 판단은 배포 적합성 미판정이다.** 메모리가 실제 4GB라면 데이터베이스·공용 서버·다섯 웹 서비스와 운영체제를 함께 실행할 때 여유가 작은지부터 측정해야 한다. 실제 소비량과 동시 업무 부하를 측정하지 않아 “40명 수용 가능”이나 필요한 증설량을 확정하지 않는다. 컨테이너가 가용 메모리를 넘기면 프로세스가 종료될 수 있으므로 유휴 상태의 기동 성공만으로 판단하지 않는다. [Docker 자원 제약 문서](https://docs.docker.com/engine/containers/resource_constraints/)

현재 작업공간 배포 파일에는 서비스별 처리장치·메모리 상한이 명시되지 않았다. 공용 서버라면 기존 업무와의 자원 경합을 확인하고 측정 결과에 맞춘 할당안을 승인받아야 한다. 실제 제한값은 이번에 변경하지 않는다. 빌드와 실행의 메모리 소비는 따로 측정한다. 빌드 중 부족하면 별도 빌드 환경에서 만든 같은 버전의 이미지를 배포하는 안을 검토하며, 아직 그 배포 경로를 적용·검증한 것은 아니다. [Next.js 메모리 측정 안내](https://nextjs.org/docs/app/guides/memory-usage)

### 서버 담당자에게 전달할 확인 요청

> 최대 약 40명의 직원이 사내망·회사 원격접속으로 사용할 업무 서비스를 준비하고 있습니다. 제공된 개발용 서버의 현재 사양과 실제 여유 메모리·디스크, 별도 데이터/백업 저장소, 다른 업무와의 공용 여부, 운영용 전환 가능 여부를 확인해 주세요. 기존 설정 변경이나 설치 없이 조회만 부탁드립니다. 계정·비밀번호는 회신에 포함하지 않아도 됩니다.

서버 담당자가 승인된 접속 절차로 확인할 읽기 전용 명령 예시다. Docker 명령은 이미 설치되어 있고 조회 권한이 있는 경우에만 실행한다. 아래 명령을 현재 개발 워크스페이스에서 실행한 결과를 해당 사내 서버 사양으로 대체하지 않는다.

```bash
cat /etc/os-release
uname -m
nproc
free -h
df -hT
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
docker version
docker compose version
docker stats --no-stream --format 'table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}'
```

## 최대 40명 기준의 용량 검증 계획

전체 인원은 사용자가 알려준 상한이며 동시 사용량은 아직 측정하지 않았다. 서버 적합성 판단에는 서버 전체 사양보다 이 서비스에 실제 할당할 자원과 기존 업무의 사용량을 확인한다. 문서/첨부 저장량과 백업 보관량도 별도로 산정한다.

운영 데이터를 건드리지 않는 검증 환경에서 동시 활동을 단계적으로 늘려 최대 40명 시나리오까지 확인하는 안을 준비한다. 로그인 유지·목록/검색·문서 조회와 서로 다른 문서 편집·저장·첨부/출력을 섞어 응답시간, 실패 요청, 자원 사용량, 협업 잠금과 데이터 보존을 관찰한다. 같은 문서의 편집 잠금은 기존 업무 계약대로 검사하며 부하를 위해 제한을 우회하지 않는다. 실제 실행 부하·시간·합격 기준은 서버 할당 자원과 업무 패턴 확인 후 고정한다. **현재 부하 검증은 미실행**이다.

## 입력 후 실행 순서

1. **읽기 전용 확인:** 승인된 운영 설정의 필수 항목·서로 맞는 접속 주소·저장소·메일 전달·인증서·회사 정보/로고를 검사한다. 비밀 원문은 문서·증거에 남기지 않는다.
2. **출시 버전 확정:** 현재 변경 목록을 검토하고 포함 범위·커밋/게시 대상·배포 대상·영향·되돌리기 계획을 하나의 실행안으로 제시한다. 이전 빌드·검증을 새 출시 버전의 증거로 재사용하지 않는다.
3. **승인된 버전 게시·배포:** 사용자 승인 후 같은 버전의 서버와 다섯 웹 서비스를 빌드·게시·배포한다. 기존 운영 데이터가 있으면 변경 전 백업과 기존 버전을 확보한다. 데이터 구조 변경은 현재 운영 상태와 비교한 뒤 승인된 순서로 적용한다.
4. **실제 운영 검증:** 아래 다섯 증거를 같은 출시 버전에 연결한다. 운영 설정/회사 정보 적용은 기존 권한·감사 기능을 사용한다. 운영 자료를 대상으로 테스트용 생성·수정·삭제를 임의 실행하지 않는다.
5. **최종 인수:** 고객관리 회사 정보·견적 출력물, 프로젝트·커뮤니티를 포함한 다섯 서비스의 실제 접속·주요 동선과 사용자 확인을 마친다. 실패가 있으면 공개 완료를 선언하지 않고 원인·복구 결과를 기록한다.

## 실제 운영 완료 기준

| 증거 묶음 | 완료 조건 | 현재 |
|---|---|---|
| 출시 버전 | 미커밋 변경 없이 확정된 버전, 원격 게시 상태와 검증/배포 버전 일치 | 미완료 |
| 운영 기반 | 실제 설정·접속 주소·인증서·인증·저장소 준비 상태 통과 | 미완료 |
| 백업·복구 | 운영 자료의 백업을 격리된 대상으로 복원하고 데이터·파일 일치 확인 | 미완료 |
| 운영 제어 | 같은 출시 버전에서 관리·문서 운영 기능을 격리 검증하고 변경을 복원 | 미완료 |
| 배포 화면 | 실제 배포 주소의 큰 화면·휴대폰, 관련 요청·실행 오류 없는 동작 증거 | 미완료 |

다섯 묶음은 검사 단위이지 서비스 개수가 아니다. 기존 문서·관리 자동 검사만으로 나머지 서비스의 운영 인수가 끝났다고 판단하지 않는다. 고객관리의 최종 검증은 승인 회사 정보·로고 대조, 새 브라우저 증거와 실제 견적 출력물을 추가로 요구한다. 프로젝트·커뮤니티도 승인된 실제 주소에서 확인한다.
