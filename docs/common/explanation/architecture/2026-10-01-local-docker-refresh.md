# 현재 작업 기준 로컬 Docker 갱신

> 2026-10-01 · 로컬 반영 및 로그인 기본 검증 완료

사용자 요청에 따라 오류 공용화, 홈·탭 공용화, CRM 사업연도와 플랫폼 공통코드 이전을 포함한 현재 작업트리를 로컬 Docker에 반영한다. 실행 구성은 `compose.yaml + compose.local.yaml`, 기존 `ssoo_dev` DB와 DMS `dev` 문서 경로를 유지한다.

## 데이터 보존과 이전

- 원래 이미지 ID와 문서 114개 hash를 `output/local-deploy/20261001/`에 기록했다. 기존 이미지에는 `before-refresh-20261001` 태그를 남겼다.
- DB 백업은 같은 디렉터리의 `private-backup/`에 두며 디렉터리 0700, 파일 0600으로 제한한다. Git과 Docker 빌드 컨텍스트에서 제외되는 로컬 복구용 자료다.
- 기존 DB는 launch 이력 도입 전 호환 DB다. baseline 강제 등록이나 전체 `db push`는 수행하지 않는다.
- 복제 DB에서 `20260930090000_move_crm_business_years`, `20260930100000_move_common_codes`를 순서대로 실행했다. 사용자 11명, 공통코드 134개, 사업연도 3개를 보존했고 공통코드 master hash가 일치했다. 85개 이력 트리거가 활성 상태다.
- 이전 중 기존 권한 테이블에 `updated_at` 기본값이 없어 실패하는 경우를 발견했다. 권한·역할 연결 INSERT에 수정 시각을 명시하도록 보완하고, 기본값 없는 기존 DB를 재현하는 회귀 검증을 추가했다. 전체 baseline 14개 migration·85개 트리거·schema drift 0과 populated 복원을 통과했다.
- 기존 계정의 비밀번호·업무 데이터를 덮는 데모 시드는 재실행하지 않는다. 검증된 두 migration과 이력 트리거만 적용하며 서버·다섯 웹은 `up --no-deps --no-build`로 교체한다.

## 반영과 확인

- DB 준비·서버·다섯 웹 이미지를 직렬 빌드했고, 서버와 다섯 웹 컨테이너를 현재 이미지로 교체했다. 서버 readiness와 다섯 웹 healthcheck, 기존 PostgreSQL 상태가 모두 정상이다.
- 운영 중인 컨테이너의 마운트 경로와 PostgreSQL 컨테이너·볼륨을 유지했다. 예전 `ssoo-db-init` 종료 컨테이너는 재실행하지 않았으며 새 준비 이미지는 트리거 설치에만 사용했다.
- 실제 DB에서도 사용자 11명·공통코드 134개·사업연도 3개, 공통코드 행 hash, 이전 직전/직후 계정 인증 행 hash가 일치했다. 이력 트리거 85개가 모두 활성 상태다. 문서 114개의 경로·내용 hash가 모두 일치했다.
- 현재 서버 이미지에 포함된 앱·공용 패키지 소스 1,553개를 작업트리와 대조해 차이 0건을 확인했다.
- 실제 브라우저에서 다섯 서비스 모두 기존 관리자 로그인 → 홈 진입 → 사용자 메뉴 로그아웃 → 로그인 화면 복귀를 통과했다. 각 로그인·로그아웃 응답은 200이며 해당 실행 동안 HTTP·콘솔·런타임 오류가 없었다. 첫 검증 스크립트의 직접 로그아웃 요청은 필수 Bearer 인증 없이 호출해 401이었으며, 실제 사용자 메뉴를 이용하도록 검증 도구를 수정한 뒤 통과했다.
- 다섯 로그인 화면에서 회원가입·가입 요청 링크는 표시되지 않았다. 회원가입 절차가 동작한다고 검증한 것은 아니며 다음 업무 검토에서 이 진입 상태부터 확인한다.
- 기존 DB의 `updated_at` 기본값 부재 회귀, 전체 baseline 검증, preflight와 규칙 동기화 검사를 통과했다. 이번에 만든 검증용 복제 DB와 브라우저 세션은 정리했다.

로컬 증거는 `output/local-deploy/20261001/verification.json`과 빌드·이전 로그, `output/playwright/local-deploy-20261001/auth-smoke.log` 및 화면 캡처에 남겼다. 초기 백업과 교체 직전 백업은 `private-backup/`에 보관한다.
