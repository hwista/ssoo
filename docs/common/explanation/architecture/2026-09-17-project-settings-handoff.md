## 승인과 구현 범위

사용자는 구체적인 적용안 제시 이후 “진행하자”로 별도 프로젝트 설정 진입, 사용자별 저장, 내 프로젝트의 세 보기, 완료 작업 표시, 담당자 선택, 두 업무 알림을 승인했다. 새 승인 번호를 만들지 않았다. [승인 범위](../../../pms/planning/2026-09-17-settings-approval-proposal.md)와 [사용 가이드](../../../pms/guides/project-settings.md)를 따른다.

| 화면·기능 | 실제 동작 |
|---|---|
| 프로젝트 사용 설정 | 사용자 메뉴·직접 접속·로그인 복귀·새로고침. 개인 프로필·비밀번호 설정과 분리 |
| 계정별 저장 | 서버에 계정별 네 옵션 저장. 다른 기기 재조회, 저장 성공 확인, 실패 값 보존·재시도, 계정 전환 격리 |
| 내 프로젝트 | 기존 카드 보드 보존, 같은 데이터의 목록·타임라인 추가. 상세 열기 유지. 현재 단계 일정 누락·불완전 기간 명시 |
| 작업 표시 | 완료 작업만 숨김. 숨긴 수·다시 표시 제공. 취소 작업, 원본 합계·공수 기록·입력 대상 보존 |
| 담당자 선택·배정 알림 | 활성 프로젝트 멤버·활성 계정·접근 권한 확인. 생성과 실제 변경 시 새 담당자에게 전달. 자기 배정·해제·동일 값 제외 |
| 이슈 변경 알림 | 정식 이슈 실제 변경 시 현재 담당자·등록자에게 전달. 중복 수신자·변경자 제외. 정렬·메모만 변경하면 알림 없음 |

알림 설정을 끄면 이후 해당 종류만 생성하지 않는다. 과거 알림을 삭제하거나 다시 켤 때 소급 생성하지 않는다. 기존 보고서 승인 알림은 그대로 유지한다. 신규 두 알림은 해당 프로젝트의 작업·컨트롤 탭으로 이동하며 외부 접속·새로고침도 확인했다.

## 내부 보완과 보존

업무 변경과 알림 기록을 한 트랜잭션으로 처리하며 실제 저장된 이전 값과 비교한다. 수신자 설정 수정과 알림 생성은 같은 계정 잠금을 사용한다. 알림 저장 실패 때 업무 변경도 롤백한다. 현재 URL 프로젝트와 작업의 소속이 다르면 조회·수정·삭제를 거부한다. 중복 작업 코드 재전송은 충돌 안내와 함께 거절한다.

최종 재검토에서 진행 중 조회가 저장 성공 값을 덮는 경합을 막고, 조회 실패 시 안내와 실제 기본 표시가 일치하도록 보완했다. 이미 저장된 이전 프로젝트 설정 탭도 복원 가능하게 유지했다. 소유자가 없는 이전 브라우저 저장값은 자동 이관·삭제하지 않는다.

문서관리 화면·요청/응답·편집/공유/권한과 고객관리 계약·승인·청구는 변경하지 않았다. 공통 알림 서비스에는 트랜잭션 내 기록과 커밋 후 전달 기능만 추가했으며 기존 호출 방식은 유지했다.

## 완료 집계와 남은 범위
