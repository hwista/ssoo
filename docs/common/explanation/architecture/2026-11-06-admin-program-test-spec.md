# Admin 프로그램 설계 인수 테스트

> 설계 정본: [프로그램별 사용성 설계](2026-11-06-admin-program-design.md) · 도구: playwright-cli · 기존 http://localhost:3000

## 판정 규칙

- desktop 1440×1000, mobile 390×844에서 P01~P17 모두 제목/경로/recipe/본문/작업 접근성과 가로 넘침을 검사한다.
- 각 실제 처리 전 원본/fixture ID를 기록한다. 전용 사용자·조직·권한·코드·신청만 변경한다. 기존 관리자와 기존 운영 자료는 mutation 대상으로 사용하지 않는다.
- HTTP 4xx/5xx, proxy 실패, 관련 requestfailed, console warning/error, pageerror는 정상 흐름에서 실패다. 의도한 실패 주입은 정확한 요청과 상태만 별도 기록하고 복구 후 정상 재실행한다. SSE의 명시적 page navigation 취소는 업무 실패와 구분한다.
- 성공 문구뿐 아니라 재조회/새로고침/관련 진단/이력에서 실제 저장 결과를 확인한다. 취소·날짜 역전·중복 제출·조회 실패·저장 실패·revision 충돌·재진입을 변경 영향에 맞게 검증한다.
- 자동화는 화면 준비/응답을 기다린다. 고정 짧은 sleep으로 로딩 중을 결함으로 판정하거나 DOM에 값을 직접 주입해 사용자 입력을 우회하지 않는다.

## 프로그램별 브라우저 증거

| ID | 시작 / 단계 | 기대 결과와 요청·이동 |
| --- | --- | --- |
| P01 | `/organizations`: 전용 회사 등록→하위 조직 추가→이름 수정→관계 상세→소속 관리 | 부모 ID 저장, 경로 표시, 올바른 조직 조건 이동. 원복/중지 전 영향 확인. 관계 상세에 소속/이용권 편집 폼 없음 |
| P02 | `/users`: 전용 사용자 등록→검색→기본정보 수정→관계 연결 | 중복 식별자 오류에서 입력 유지; 수정 재조회; 사용자 ID로 담당 화면 이동, 사용자 화면에 다른 프로그램 편집 없음 |
| P03 | `/memberships?userId=…`: 대상 검색/선택→배치→기간 수정→조직 이동→종료 | 실제 membership 생성/수정/종료; 시작>종료 제출 차단; 대상 유지; 이동의 이용권 회수 확인; 취소 시 저장 없음 |
| P04 | `/accounts?userId=…&search=…`: 전용 계정 상태 확인→잠금 해제/시험 세션 회수 | 대상 계정 상세 자동 진입, 정확한 ID 요청, 서버 상태 재조회; 기본정보 편집은 사용자 프로그램 연결 |
| P05 | `/applications`: 5앱 기준 확인→PMS 이용권 보기→새로고침 | 정확한 앱 링크와 serviceCode 필터 유지. Admin에는 업무 앱 이용권 부여 동작을 만들지 않음 |
| P06 | `/service-grants?userId=…&organizationId=…`: 부여→역할/기간 변경→회수→재부여 | grant 저장과 diagnosis 변화, 만료된 재부여 입력 안내, 회수 이력, 다른 이용권의 효과 보존 |
| P07 | `/roles`: 전용 역할 선택→권한 선택→차이 확인→저장→원복 | 추가/제거 목록과 저장 payload 일치; 역할 전환 취소 시 초안 유지; revision 충돌 시 무단 덮어쓰기 없음 |
| P08 | `/organization-permissions?organizationId=…`: 부여→기간 변경→회수 | 대상 조직에 직접 적용, 저장 결과/이력; 역전 기간 차단, 다른 조직에 확장되지 않음 |
| P09 | `/user-permissions?userId=…`: 허용/차단→진단→회수 | 대상 사용자 고정, 예외 효과와 판정 일치, 회수 후 다른 허용 경로 재확인 |
| P10 | `/access-diagnosis?userId=…`: 판정→원인별 담당 화면→처리 후 재진단 | 같은 사용자 ID 유지, 실제 서버 판정, 진단 화면에 편집 폼 없음; 원본 식별자와 세부 권한 조회 유지 |
| P11 | `/approval-authorities`: 전용 적격 담당자 검색→범위/기간 설정→저장→회수 | 후보 조건·범위 요약·실제 위임 일치; 만료 입력 차단, 위임 이력, 담당 범위 외 권한 확대 없음 |
| P12 | `/approvals`: 전용 신청 상세→사유→승인/반려→완료 내역 | 처리 결과와 생성된 관계/이용권 확인; 중복 처리 방지; 다른 관리자의 선처리는 오류 후 재조회로 확인 |
| P13 | 각 기록의 이력 버튼→`/operation-history?...`→전후 비교→전체 필드→관련 관리 | category/subjectId 등 실제 필터 적용, ID/원본 보존, 변경 필드 표시, 새로고침 조건 유지 |
| P14 | `/codes`: 그룹 선택→전용 코드 생성→표시명/순서 수정→참조→중지/삭제 | 그룹과 실제 저장 일치, 숫자 검증, 사용처 확인, 기존 source-compatible 보존 |
| P15 | `/auth`: 적용값 확인→무해한 값 변경→미저장 표시→새로고침 취소→저장→원복 | 편집값 보존, 성공 후 적용값 재조회, 원본 복원. 로그인 방법/외부 제공자/비밀값은 시험 중 변경하지 않음 |
| P16 | `/email-operations`: 업무 선택→전용 로컬 시험 기록→상세/재시도/수신함 | 영역 선택으로 작업 집중, 다른 영역 복귀 가능, 외부 전송 없이 실제 로컬 보관 확인; 원본 운영 설정 유지 |
| P17 | `/ai-operations`: 업무 선택→전용 작업 상세→재시도 등록→후속 작업 확인 | 원본 실패 기록 보존, 새 작업 연결과 상태 조회, 유료 호출 및 전체 큐 실행 없음; 외부 실행 미검증은 구분 |

## 회귀 게이트

1. 설계 책임 검사: 사용자/조직/진단 안에 다른 프로그램의 편집 패널이 없고 기존 담당 화면·메뉴 17개가 유지된다.
2. 문맥 계약 검사: route 조건 parsing/encoding, 동일 탭의 다른 대상, 조건 해제, 새로고침. 단위 검사는 의미 있는 조건/기간 경계에 한정한다.
3. `codex:preflight`, `codex:verify-sync`, Admin lint/타입/빌드, UI 소비·스타일 경계·입력 inventory, `verify:ssoo-frame`, `verify:error-recovery`, 문서 검사.
4. `codex:platform-guard`: 서버+5앱. 서버 테스트 캐시 재사용 여부를 기록하고 새 로직의 표적 검사는 실제 실행한다.
5. 최종 배포본 34개 화면과 P01~P17의 처리/조회 동선. 시험 데이터 정리는 소유 fixture만 수행하고 결과를 기록한다. cleanup 실패가 있으면 완료로 처리하지 않는다.

## 증거와 반복

증거 디렉터리 `output/playwright/admin-program-design-20261106/`. 설계 검토→구현→검사 실패→원인 구분→보완→재검사의 이력을 결과 문서에 남긴다. 체크리스트를 통과하도록 오류를 숨기거나 검증 범위를 축소하지 않는다. 미지원 외부 환경은 내부 처리/표시 검증과 외부 성공을 분리해 보고한다.
