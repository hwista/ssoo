# 계약 문서 역할별 생성 기록 처리 결과

> 후속: 이 문서에서 남겨둔 알림 연결 오류는 [수정·검증 기록](2026-09-17-notification-stream-handoff.md)에서 최신 상태를 확인한다.

> 후속 결과: 사용자가 단순 내부 승인 적용을 추가 승인하여 [실제 승인자 지정·요청·처리 구현](2026-09-17-contract-internal-approval-handoff.md)을 완료했다. 아래의 미구현 표기는 당시 범위를 설명하는 이력이다.

> 2026-09-17 · 승인-01의 1번 처리안 완료 · 22항목 중 19완료·3잔여 · 실제 운영 증거 0/5

사용자가 “일단 1번으로”라고 선택하여, 계약 문서에 붙는 자동 기록의 의미를 명확히 표시했다. [승인 범위](2026-09-17-contract-approval-review.md)의 생성 기록 보정만 적용한다. **담당자 지정·결재 요청·개별 승인·반려는 이번에 구현하지 않았으며, 실제 결재 기능으로 완료 집계하지 않는다.**

## 보존한 계약

요청·응답의 필드, 기존 승인 상태값·시각값, 완료 상태값, 역할 정책, 권한, 파일 경로·종류와 계약 확정 조건을 변경하지 않았다. 생성 기록의 표시와 새 기록 문서의 본문만 달라진다. 과거 값의 의미를 사람의 개별 결재 증거로 확대하지 않는다.

제품 수정은 계약 화면, 문서관리 결재선 설정의 안내, 서버의 계약 기록 문서 렌더링 세 곳이다. 공용 인증·화면 패키지와 다른 서비스의 제품 소스는 변경하지 않았다. 구조·불필요 변경 검토는 같은 에이전트가 수행했으며 독립 에이전트 검토로 표기하지 않는다.

## 검증

- 관련 서버 검사 **27/27**. 서버·고객관리 새 빌드와 문서관리 필수 가드·새 빌드, 변경 파일 린트 통과.
- 기존 기록의 표시, 새 생성 기록의 표시, 문서관리 설정 안내를 각각 **1440×1000·1366×768·390×844**에서 실제 브라우저로 확인. 최종 안내문이 화면 너비 안에 들어오는지 측정하고 작은 화면 증거를 직접 확인했다.
- 실제 정책에 검증 역할을 추가·저장·재조회하고, 같은 사람의 두 역할과 시스템 역할을 **3건의 역할 기록**으로 표시하는 것을 확인. 원래 역할 정책으로 복원했다.
- 실제 계약 초안 저장·갱신과 산출 실행·확인창·새로고침을 확인. 별도 승인 요청 기능으로 검증한 것이 아니다.
- 서버 요청·문서 대조 **13/13**: 응답 구조, 단계·산출물 종류, 기존 상태값, 새 기록 네 종류의 안내, 이전 기록 네 파일의 지문 불변, 이전·신규 Word/PDF 다운로드 및 내용 확인, 재조회 완료값 유지.
- Word 파일은 압축 문서의 본문을 다시 읽었으며 PDF는 다운로드와 파일 식별자를 확인했다. 이번 범위에서 PDF 전체 시각 품질을 새로 검수한 것으로 확대하지 않는다.
- 기존 고객관리 **2/2**·문서관리 **4/4** 회귀 통과. 격리 검증 계약과 문서는 활성 자료 0건으로 정리했고 기록 문서 24개·산출 파일 4개를 제거했다. 계약의 비활성 이력은 보존하며 전체 물리 행 삭제로 표기하지 않는다. 추가 역할은 원복하고 검증 브라우저를 닫았다.

[검증 묶음](../../../../output/playwright/approval01-records-20260917/)에 실행 스크립트·로그·화면·응답 비교·과거 파일 지문을 보존한다. 운영 자격증명·발급 토큰·비공개 실행 환경값은 증거 묶음에 저장하지 않는다. 재현 스크립트의 계정은 격리 환경의 기존 검증 계정이다.

## 실패·보완 및 별도 관찰

첫 작은 화면 검사에서 문구 존재 조건은 통과했지만 화면을 직접 확인하니 내용이 잘렸다. 이를 시각 통과로 인정하지 않고 너비를 보정한 뒤 새 고객관리 빌드로 다시 확인했다. 기동 완료 전 접속 실패는 준비 상태 확인 뒤 재실행했다.

브라우저 도구가 확인창에서 먼저 반환했으므로 그 반환만으로 생성 검증을 완료 처리하지 않았다. 실제 요청 응답과 완료 후 화면 검증 결과를 별도로 수집했다. 기존 초안 갱신 확인창도 실제로 처리했다.

계약 기록·설정 검증의 최종 수집 범위에서 관련 요청 실패·실행·콘솔 오류는 0이다. 다만 수정 전후 문서관리의 별도 알림 연결에서 `ERR_CONTENT_LENGTH_MISMATCH`를 관찰했다. 계약 기록 변경과 별개이며 해결했다고 주장하지 않는다. 알림 응답 중계에서 대체 응답에 원래 본문 길이가 남는지 다음 내부 점검 대상으로 삼는다. 원인은 아직 실행 검증으로 확정하지 않았다. 이 관찰을 새 사용자 승인 번호로 만들거나 실제 운영 통과로 숨기지 않는다.

## 출시 범위와 다음 작업

승인-01의 완료는 사용자가 선택한 생성 기록 의미 보정의 완료다. 실제 담당자별 결재는 이번 출시 처리 범위에서 제외된 미구현 기능으로 남는다. 향후 필요하면 역할·담당자·권한·문서 버전·승인/반려 절차를 별도 설계·승인해야 한다.

**승인 항목 19/22 완료·3잔여**다. 신규 승인 번호 0, 완료 +1이며 실제 결재 기능을 완료 수에 더하지 않는다.

남은 사용자 결정은 운영 출시 환경, 프로젝트 설정의 실제 반영, 문서 다이어그램 표현이다. 실제 운영 증거 **0/5**, 운영 배포 미실행은 그대로다. 알림 연결의 내부 점검도 전체 출시 완료 전에 처리할 후속 작업이며 승인 항목 개수를 제품 완성도로 읽지 않는다.
