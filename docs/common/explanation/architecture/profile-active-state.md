# 공용 프로필의 활성 상태

> 2026-09-16 · 승인-19·20 · 실행 증거와 완료 상태는 출시 핸드오프를 따른다.

## 조회와 표시

관리·고객관리·프로젝트관리·문서관리·커뮤니티는 같은 공용 프로필을 사용한다. 서버 조회는 활성 계정의 활성 프로필만 반환한다. 실제 조회 시점의 상태를 기준으로 하며 변경 직후의 조회 갱신은 아래 승인-20 기준을 따른다. 비활성 프로필은 본인이 조회하더라도 기존 찾을 수 없음 응답과 다시 시도 안내로 처리하며, 조회를 이유로 재생성하거나 활성화하지 않는다.

기술은 보유 관계와 기술 원본이 모두 활성인 항목만 표시한다. 기존 활성 경력 조건과 이름·사진·소개·팔로우·게시물·편집 화면 및 응답 필드는 유지한다. 이 기준은 기존 활성 상태를 적용한 것이며 별도의 비공개 프로필 설정을 구현했다는 의미가 아니다.

이미 열린 프로필의 재조회가 찾을 수 없음으로 끝나면 이전 프로필 내용·편집값·게시물 표시를 비운다. 같은 안내의 다시 시도로 조회를 재실행한다. 일시적인 서버 오류나 다른 조회의 실패는 프로필이 비활성이라는 뜻으로 취급하지 않는다. 다른 활성 사용자의 숨겨진 기존 탭을 삭제하는 변경도 아니다.

## 수정과 최초 생성

비활성 프로필의 수정과 경력 추가는 저장 전에 거절한다. 이름만 바꾸는 요청도 먼저 활성 프로필을 확인하므로 거절된 요청이 사용자 정보를 바꾸지 않는다. 활성 프로필의 수정·알림과 실제로 프로필이 없는 활성 사용자의 최초 생성 동작은 유지한다.

자료 삭제·일괄 정리·스키마 변경이나 DMS 문서 업무의 요청/응답 변경은 포함하지 않는다. 기존 활성 확인과 저장 사이에 다른 요청이 상태를 변경하는 모든 동시성까지 새로 보장하는 변경은 아니다.

## 변경 직후 표시 갱신

사용자 승인-20으로 팔로우·좋아요·북마크·소개/개인 설정 저장과 기존 관련 변경 알림에서 해당 프로필·게시물 및 필요한 계정 조회를 새로 읽는다. 본인 조회 별칭도 함께 갱신한다. 일반 진입·포커스 조회의 기존 5초 응답 재사용은 보존한다.

변경 알림이나 조회 대상 전환 이전에 시작한 응답은 최신 표시를 덮어쓰지 않는다. 이미 진행 중인 조회가 끝나면 기존 재조회 큐로 최신 상태를 읽는다. 실패한 저장을 성공으로 표시하지 않으며, 입력 중인 값과 수동 재시도·404/일시 오류의 구분을 유지한다. 알림 없이 발생한 모든 외부 변경의 즉시 감지까지 보장하는 계약은 아니다.

[갱신 핸드오프](2026-09-16-profile-refresh-handoff.md)에 다섯 서비스의 실제 검증과 보존 범위를 기록했다. 요청 검사는 `node scripts/verify-profile-refresh.mjs`로 재실행할 수 있다.
