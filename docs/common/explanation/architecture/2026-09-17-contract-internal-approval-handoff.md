# 계약 초안 내부 승인 — 적용 및 검증 기록

> 후속: 이 문서에서 남겨둔 알림 연결 오류는 [수정·검증 기록](2026-09-17-notification-stream-handoff.md)에서 최신 상태를 확인한다.

> 작성: 2026-09-17 · 상태: 구현·검증 완료 · 기존 승인-01 확장 범위 · 전체 19완료·3잔여

## 사용자 승인 범위

사용자는 자동 생성된 역할별 기록 설명 이후, 시스템 내부의 단순 승인 흐름을 적용하도록 승인했다. 기존 승인 항목 01의 추가 범위이며 새 승인 항목을 만들지 않는다.

- 저장된 계약 초안의 내용을 확인하고 실제 승인자 한 명을 지정해 요청한다.
- 지정된 승인자 본인만 승인하거나 사유를 입력해 반려한다.
- 요청자는 미처리 요청을 철회하고 다시 요청할 수 있다.
- 요청 당시 초안, 요청자·승인자, 처리 시각과 사유를 보관한다.
- 계약 또는 초안이 바뀌면 이전 승인을 현재 초안의 승인으로 표시하지 않는다.
- 기존 문서 공유 권한을 그대로 적용한다. 승인자 지정이 열람 권한을 자동으로 부여하지 않는다.

## 유지하는 경계

자동 생성되는 역할별 기록과 실제 사람의 승인 이력은 별개다. 기존 문서 생성·다운로드, 계약 확정, 청구, 인계 조건과 문서 관리 화면·인터페이스 계약은 바꾸지 않는다. 승인 대상은 저장된 계약 초안이며, 생성된 배포 문서나 외부 전자서명의 승인으로 확대 해석하지 않는다.

## 검증 기준

실제 서로 다른 계정으로 요청·승인·반려·철회·재요청을 확인한다. 자기 승인, 다른 사람의 대리 처리, 권한 없는 열람, 비활성 계정 지정, 중복 요청·중복 처리, 문서 변경 후 오래된 요청 처리를 차단하는지 검증한다. 요청 당시 내용과 현재 내용이 달라졌을 때 이력을 보존하는지도 확인한다.

새 데이터 구조는 빈 검증 데이터베이스의 배포 이력·트리거·복원 검증을 통과해야 한다. 화면은 데스크톱과 휴대폰 폭에서 실제 브라우저로 확인한다. 공통 타입 변경에 따라 서버와 다섯 서비스의 빌드, 기존 문서 관리 회귀 검증, 문서·규칙 검증을 실행한다.

## 기능별 결과

| 기능·화면 | 결과 |
|---|---|
| 승인 요청 | 저장된 초안 확인 후, 열람 권한이 있는 다른 활성 사용자 한 명에게 요청 |
| 내 승인 대기 | 계약현황과 계약 원장에서 자신의 대기 요청을 찾아 계약으로 이동 |
| 승인·반려 | 지정된 본인만 처리. 요청 당시 초안 확인 후 활성화, 반려 사유 필수 |
| 철회·재요청 | 요청자가 미처리 요청을 철회. 반려·철회 후 다시 요청 가능 |
| 처리 이력 | 요청자·승인자·시각·사유·요청 당시 내용을 보존. 재시도로 이력 중복 생성 안 함 |
| 문서 변경 | 오래된 요청의 처리를 차단하고 기존 승인을 현재 초안에 적용하지 않음. 파일 생성 기록만 추가된 경우에는 승인 유지 |
| 권한 회수 | 원본 권한을 회수하면 보관된 초안 열람과 승인도 차단. 자동 권한 확대 없음 |

검증 중 실제로 발견한 초안 권한 등록 누락, 계약 목록의 대기 진입점 누락, 파일 생성 기록과 문서 변경의 구분을 보완했다. 자동화가 이전 이력의 초안을 선택한 경우에는 승인 버튼이 비활성 상태를 유지했고, 현재 대기 요청을 확인한 뒤 재검증했다. 화면 전환 중 캡처를 최종 외관으로 간주하지 않고 효과가 끝난 화면도 직접 확인했다.

검증 근거는 `output/playwright/approval01-internal-20260917/`에 보존한다. `api-results.json`, `history-evidence.json`, `browser-flow.json`, `browser-stale.json`, `visual-check.json`, `db-constraints.json`, `regressions.json`, `cleanup.json`, `review.md`와 실행 로그를 함께 확인한다. 설계 검토와 불필요한 변경 검토는 동일 작업자가 수행했으며 독립 검토자 승인으로 주장하지 않는다.

## 보존 및 정리

검증용 계약과 문서·생성 파일을 정리하고 승인·철회·반려의 감사 이력은 보존했다. 기존 문서 관리 화면, 기존 요청·응답 계약, 역할별 자동 기록과 생성 상태값은 변경하지 않았다. 데이터 구조 문서 도구는 고객관리 영역 분리와 잘못된 교차 참조를 보완했고 고객관리 문서만 내보냈다. 다른 서비스의 기존 다이어그램은 변경하지 않았다.

## 완료 판정과 남은 범위

사용자가 후속으로 승인한 **단순 내부 승인 범위는 완료**했다. 기존 승인 항목 01 안에서 처리했으므로 신규 항목 0·전체 완료 건수 추가 0이며, 전체는 **22항목 중 19완료·3잔여**다. 잔여는 승인-06 운영 환경, 승인-13 프로젝트 설정 반영, 승인-15 문서관리 다이어그램이다.

여러 단계 결재선, 외부 전자서명, 배포 문서 전체에 대한 승인, 기존 계약 확정·청구를 막는 필수 승인 조건은 이번 범위에 포함하지 않는다. 앞선 자동 기록 보정 결과와 이번 실제 승인 구현을 구분한다.

실제 운영 증거는 계속 **0/5**이며 운영 배포·커밋·푸시는 하지 않았다. 앞선 문서관리 알림 연결 오류 관찰은 별도 내부 점검 대상으로 남아 있고 이번 계약 승인 브라우저의 오류 0과 혼동하지 않는다.
