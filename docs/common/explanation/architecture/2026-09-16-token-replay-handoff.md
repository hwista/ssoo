사용자 “진행하자”로 이전 토큰 재사용 차단, 동시 복원·빠른 로그아웃 보완 및 기존 사용자의 한 번 재로그인 전환을 승인받았다. 격리 검증 환경에 적용했으며 실제 운영 배포는 실행하지 않았다.

## 구현과 보존 범위

갱신 토큰 전체의 버전 표기 SHA-256 요약값과 매회 고유 식별자를 사용한다. 현재 값·사용자·미철회·미만료 조건을 원자적으로 교체하며 갱신으로 세션 철회를 되돌리지 않는다. 사용자 비밀번호 저장 방식이나 데이터베이스 구조는 변경하지 않았다.

공통 로그인 복원 요청은 화면을 떠나도 작은 교체 응답 수신을 마무리한다. 같은 실행 문맥의 중복 요청은 합치고, 로그아웃 시 진행 중인 인증 요청을 취소하며 이전 작업의 응답이 새 인증 상태를 덮지 않게 한다. 정상 서명 토큰이 이미 교체된 경우에만 최대 다섯 번 같은 주소로 재요청해 브라우저의 최신 HttpOnly 쿠키를 사용한다. 이전 토큰을 유예 허용하거나 서버에 토큰 원문 캐시를 두지 않는다.

파일·이벤트 중계는 현재 쿠키를 검증하는 별도 인증 경로를 사용하여 다운로드 취소가 쿠키 교체를 만들지 않는다. 실제 교체 후의 이전 쿠키는 이 경로에서도 거절한다. 빈값·위조·만료·철회·권한·요청 제한·서버/통신 오류의 의미와 기존 이벤트 재시도 응답을 유지했다. 다섯 서비스의 15가지 고의 실패 상태와 보호된 자료/위조 방지 요청 거절도 확인했다.

문서관리 화면·업무 요청 형식, 다섯 앱별 화면 소스와 공용 화면 틀은 이번 작업 전과 동일하다. 인증 통신 변경과 기존 세션 한 번 재로그인만 승인된 영향 범위다. 테스트한 소스와 실행 산출물 지문은 검증 묶음에서 비교한다.

## 검증과 보완 이력

관련 서버 42/42, 공용 상태·중계 실행 41/41, 새 서버와 다섯 웹 빌드, 문서관리 가드, 코드·규칙·문서 검사를 통과했다. [검증 묶음](../../../../output/playwright/approval22-token-replay-20260916/)에 실제 응답·화면·업무 회귀와 정리 증거를 남긴다. 설계와 정리 검토는 동일 에이전트가 수행했으며 독립 검토로 표기하지 않는다.

공통 연동 명세와 열람 문서도 실제 서버의 세션 확인 경로에 맞췄으며, 다섯 영역의 요청 목록 459건이 실행 서버와 일치했다. 고객관리 검증 항목 2건과 문서 업무 검증 자료 5건의 삭제를 확인했다. 별도 다운로드 검증 자료는 실패 실행분까지 정리했고 전용 인증 검증 계정도 남아 있지 않다. 검증 전후 서버·다섯 웹 산출물 지문이 일치한다.

첫 웹 빌드의 서비스 이동 검사에서 복원 응답 취소로 쿠키를 받지 못하는 문제가 발생했다. 실패를 보존하고 위의 화면 이동 보호와 파일 인증 분리를 반영한 뒤 서버·다섯 웹을 재빌드하여 최종 검증했다. 테스트 준비 데이터 누락, 검증 도구의 잘못된 요청 방식, 웹 준비 전 연결 실패도 별도 기록했다. 초기 실패를 통과 증거로 바꾸지 않았다.

## 남은 작업

완료 +1·신규 0으로 승인 항목은 **17/22 완료(77.3%), 5건 대기**다. 제품 전체 구현률이나 출시 준비율이 아니다. 남은 대상은 계약 문서 승인 기록의 업무상 의미, 커뮤니티 공유·첨부, 프로젝트 설정의 진입과 반영, 문서 다이어그램 표현, 운영 출시 환경이다. 문서관리 검수 동작과 사용 방식은 계속 사용자 승인 기준을 따른다.

실제 운영 증거 **0/5**가 남아 있다. 로컬 검증을 운영 배포·공개 접속·복구 검증으로 대체하지 않으며 출시 완료로 판정하지 않는다.
