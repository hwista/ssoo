# 검색 결과 표현 승인 적용 핸드오프

> 작성: 2026-09-22 · 상태: 승인 범위 적용·브라우저 검증 완료

## 승인과 범위

사용자는 [현재/제안 비교](../../../../output/playwright/search-review-20260922/review.html)를 확인한 뒤 “적용하자”로 승인했다. 다섯 서비스가 사용하는 공통 검색 카드의 표시만 변경한다. 서비스 선택 탭, 검색 조건·결과 수·순서·대상 이동·서버 응답 계약, 문서관리 전용 문서 카드·검색 기록·도우미는 유지한다.

- 서비스 이름과 고객 유형·활동 수·영업기회 상태·우선순위·역할·프로젝트 상태/단계·게시물 공개 범위를 기존 업무 화면 용어로 표현한다.
- 고객 코드/담당자, 영업기회 고객/담당자, 프로젝트 상태/진행 단계를 표시하고 내부 식별번호는 숨긴다. 문서 실제 위치는 유지하며 항목명만 한글화한다.
- 시스템 이동 주소는 서비스 이름으로 대체한다. 원본 결과의 경로·식별번호·권한은 변경하지 않는다. 긴 메타정보는 카드 안에서 줄바꿈한다.
- 결과 종류별로 확인된 코드만 변환한다. 작성자가 쓴 설명·본문·문서 요약은 유지하며 알 수 없는 값은 원문을 남긴다. 생성된 요약의 알려진 상태/역할 끝부분과 프로젝트 코드 조합만 변환한다.

구현은 공용 검색 카드와 표시 보조 함수, 해당 회귀 검증 스크립트에 한정한다. 문서관리 앱과 서버 소스는 변경하지 않았다.

## 검증과 경계

[실제 적용 화면](../../../../output/playwright/search-apply-20260922/screens.html)과 [검증 상세](../../../../output/playwright/search-apply-20260922/results.md)를 참조한다.

- 표시 규칙 회귀 9/9, 공용 패키지 타입 빌드 통과.
- 다섯 서비스 fresh build 컴파일·타입 검사·생성 성공. 실제 작업공간 문서관리 보호 검사·빌드 통과.
- 브라우저 검사 140/140, 실제 데이터 화면 20개·검증용 데이터 화면 15개, 최종 예기치 않은 브라우저/통신 오류 0.
- 실제 검색 조건·결과 건수/순서·결과 내 검색·서비스 선택/전체 복귀 및 실제 결과 열기 5/5 검증. 기존 업무 탭 방식과 서비스 간 이동을 유지한다.
- 프로젝트·게시물 표시는 검증용 응답으로 확인했다. 실제 프로젝트·게시물 검색/열기 전체를 재검증한 것으로 계산하지 않는다. 권한 검증도 표시 범위이며 서버 인가 전체 재인증은 아니다.
- 문서관리 전용 문서 2건은 매 요청 생성 요약을 제외한 기존 텍스트가 일치했고 실제 문서 열기를 확인했다.

격리 빌드의 네 서비스에서는 기존 Next 내장 ESLint 플러그인 탐색 오류가 발생했다. 실제 작업공간의 변경 두 파일 별도 ESLint는 오류 0·기존 경고 1이다. 이후 설치된 플러그인 탐색 경로와 영업관리 파일 범위를 검증 프로세스에 명시해 동일 Next 검사기로 다섯 앱 883개 파일을 검사했고 오류 0으로 통과했다. 제품 설정·의존성·검사 규칙은 변경하지 않았으며 초기 오류와 최종 통과 기록을 구분해 보관했다. 관리자 최초 테스트의 주소 전환 가정과 문서관리 빌드 완료 전 최초 기동은 보정 후 재검증했으며 초기 기록도 보존한다.

실행 명령은 `node --test scripts/verify-search-result-presentation.mjs`, 공용 패키지 빌드, 다섯 웹 빌드, `pnpm run codex:preflight`, `pnpm run codex:verify-sync`, `pnpm run codex:dms-guard`, 변경 코드·문서 검사다. 운영 배포는 변경하지 않았다.
