# 현재 워크스페이스 로컬 Docker 배포

> 작성: 2026-09-23 · 상태: 로컬 배포 및 접속 확인 완료

## 요청과 범위

사용자 요청 “일단 현 기준 도커 로컬 배포부터 해봐 눈으로 한번 보게 나도”에 따라 미커밋 변경을 포함한 현재 워크스페이스로 서버·다섯 웹 앱·DB 준비 이미지를 빌드했다. 회사 서버 배포와 화면 추가 수정은 수행하지 않았다.

- 실행 구성: `compose.yaml + compose.local.yaml`, DMS 역할 `dev`.
- 기존 `ssoo_dev` DB와 `.runtime/dms/documents-dev` 문서 working tree를 유지했다. 문서 컨테이너 경로는 `/var/lib/ssoo/documents`이다.
- DB 사전 백업: `/tmp/ssoo-local-deploy-20260923-backup/before.dump` (접근 제한 0600). 임시 경로의 작업용 백업이며 장기 보관 증거가 아니다.
- `.dockerignore`에서 `output/`, `.playwright-cli/`를 제외해 화면 검증 산출물이 이미지 빌드에 복사되지 않도록 했다.

## 실행 중 복구

첫 빌드는 외부 패키지 다운로드 시간 초과로 실패했다. 재시도에서 일곱 이미지 빌드를 완료했다.

기존 로컬 DB는 정식 출시 이력 관리 이전의 호환 DB였다. 기존 AI 데이터 구조를 보호하기 위해 자동 전체 스키마 동기화가 생략되는 경로에서, 최근 계약 승인·개인 설정 테이블이 없어 새 이력 트리거 설치가 중단됐다. 네 테이블이 모두 없는 것을 조회한 뒤 아래 기존 승인 작업의 migration SQL 두 개를 변경 없이 하나의 트랜잭션으로 적용했다.

- `20260917090000_add_crm_contract_approval`
- `20260917100000_add_pms_user_settings`

기존 테이블/데이터 삭제나 baseline 이력 강제 등록은 하지 않았다. 같은 새 이미지로 다시 시작하여 DB 준비 절차가 종료 코드 0으로 완료됐고, 이력 트리거 84개가 모두 활성 상태임을 확인했다. **이 로컬 호환 DB를 정식 출시 baseline 검증 완료로 간주하지 않는다.** 새 pre-baseline DB를 다시 연결할 때에는 이 추가 구조의 존재 여부를 별도로 확인해야 한다.

| 최신 화면 | 로그인 아이디 저장·비밀번호 표시, 문서 권한 관리 제목/현재 위치/대화 버튼 확인 |

브라우저 검사 중 재로그인이 필요했던 세션과 중복 `main` 검사 선택자는 보정 후 다시 확인했다. 업무 저장·권한 변경·대화 전송은 수행하지 않았다. 기존 문서 트리 및 홈/설정 접속 확인이며, 모든 기능의 재검증 완료를 뜻하지 않는다.

빌드·시작·갱신 기록은 `output/local-deploy/20260923/`, 실제 화면과 브라우저 결과는 `output/playwright/local-deploy-20260923/`에 남겼다.

## 접속과 남은 확인

| 서비스 | 로컬 주소 |
|---|---|
| 문서관리 | <http://localhost:3003> |
| 고객·영업관리 | <http://localhost:3001> |
| 프로젝트관리 | <http://localhost:3002> |
| 사내 소통 | <http://localhost:3004> |
| 관리자 | <http://localhost:3000> |

문서관리 권한 설정은 `/settings/management/documentAccess`로 바로 열 수 있다. 배포 확인 중 1440px 화면에서도 권한 관리 요약 카드 일부 항목명이 좁게 줄바꿈되는 것을 확인했다. 이번 배포에서 임의 수정하지 않았으며, 후속 화면 비교·승인 대상으로 남긴다. 기존 검색창 배경 차이 미재현 항목도 이번 배포로 해결 처리하지 않는다. 정식 승인 대장과 전체 품질 완료 집계는 변경하지 않는다.
