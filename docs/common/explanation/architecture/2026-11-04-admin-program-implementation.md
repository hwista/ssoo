# Admin 공통 프로그램 구현·Ralph 검증 대장

> 시작: 2026-11-04 · 상태: 사용자 결정으로 외부 연동 3개 보류, 다음 공통 운영 검토로 진행 (2026-11-05)
> 목표: [17개 프로그램](2026-11-04-admin-program-catalog.md) 구현과 [15개 운영 시나리오](2026-11-04-admin-common-management-scope.md) 검증. 2026-11-05 사용자가 비용을 수반하는 외부 연동 검증을 보류하고 다음 시나리오 검토를 진행하도록 완료 조건을 조정했다.

## 최신 판정 (2026-11-05)

- 17개 프로그램의 현재 구현은 기존 로컬 배포에 반영했다. 서버와 5앱은 healthy이며 Admin 진입은 `http://localhost:3000`이다. 신규 포트·서비스·DB는 만들지 않았다.
- 최신 공용 세션 수정은 서버·5앱 platform guard를 통과했고, 5앱 비활동 로그아웃 및 만료 토큰 연동을 확인했다. 오류 안내의 버튼 가림도 수정하여 배포 후 데스크톱/모바일에서 실제 재확인→로그아웃을 검증했다.
- 조직 신청의 실제 동시 승인도 201/409 및 조직·소속 각 1건으로 확인했다. 검증 자료의 활성 계정·세션·조직·소속·이용권·위임·권한·대기 신청은 모두 종료했다. 변경 이력과 실패 메일 2건은 보존하며, 검증 AI 작업 4건은 비활성화해 worker 실행 대상에서 제외했다.
- **15개 시나리오 전체 합격은 미선언**이다. 사용자가 SMTP와 임베딩 배포 모두 없음을 확인했으므로 실제 메일 전달·사용자 복구 완료 및 임베딩 제공자 성공 복구는 미검증이다. 실제 Microsoft 외부 로그인도 미검증이며, 최초 관리자 생성은 기존 DB를 초기화하지 않고 단위 검사·관리자 교체 실검증으로 범위를 구분했다.
- `common.user.manage`는 권한 계산 기반만 지원하며 사용자 관리 API/UI 집행에는 연결되지 않는다. 이를 비관리자 사용자 관리 위임 기능으로 안내하지 않는다.
- 사용자 결정: SMTP·임베딩·Microsoft 외부 연동은 예산 확보 후로 보류한다. 위 미검증 사실을 유지하면서 현재 단계의 진행 차단 조건에서 제외한다. [설정 위치·비밀값 관리·재개 절차](../../guides/deferred-external-integrations.md)를 제공하고 [다음 공통 운영 시나리오](2026-11-05-admin-next-scenarios.md) 검토로 진행한다. 실제 유료 호출·자원 생성·worker 활성화는 실행하지 않는다.
- 보류 안내 반영 검증: 기존 Admin `/auth`, `/ai-operations`에 설정 책임·적용·재개 순서를 추가했다. Microsoft는 기존 어드민 저장 기능을 사용하고 SMTP/AI 제공자는 서버 환경변수로 적용한다. 모바일의 긴 제공자 설정 문구 잘림도 수정했다. 서버+5앱 guard와 기존 Admin 배포가 통과했으며, 1440px/390px 실제 브라우저에서 안내·비밀 입력 마스킹·설정 문구 폭을 확인했다. 169개 HTTP 응답 중 오류 응답 0, console/pageerror 0. 페이지 이동으로 취소된 SSE 5건과 대시보드 readiness 조회 1건은 별도 기록한다 (`output/playwright/admin-budget-defer-20261105/browser-guidance.json`). 최초 검증 스크립트의 읽기용 `POST /auth/me` 오분류는 수정했고 실패 기록도 보존했다. 외부 성공 검증을 대체하는 증거는 아니다.

## 실행 기준

- 기존 로컬 Admin 3000, CRM 3001, PMS 3002, DMS 3003, SNS 3004, 서버 4000을 재사용한다. 새 실행 포트·병렬 배포 환경을 만들지 않는다.
- 기존 미커밋 작업을 포함한 현재 코드가 출발점이다. 시나리오별 화면 대신 프로그램별 원본 데이터와 변경 규칙을 연결한다.
- 프로그램 단위 구현 → 테스트 → 실제 API/브라우저 → 실패 수정 → 재검증 → 아키텍처 검토 및 불필요한 중복 정리 → 최종 회귀 검증을 반복한다.
- 검증 범위를 임의로 축소하지 않는다. 사용자가 보류한 외부 연동은 성공 판정과 구별해 재개 목록에 남기고, 나머지 기능의 실제 증거와 제약을 아래 표에서 유지한다.

## 구현에 적용할 공통 운영 규칙

1. 직접 소속 배치·이용권 부여/변경은 활성 플랫폼 관리자만 수행한다. 기존 승인 위임만으로 직접 관리 권한을 부여하지 않는다. 변경 사유를 기록한다.
2. 소속의 주체와 조직은 기존 ID로 유지한다. 동일 사용자·조직의 유효기간 중복을 막고 주 소속 중복을 막는다. 전보는 기존 관계 종료와 새 관계 생성을 한 트랜잭션에서 처리한다.
3. 소속 종료는 해당 조직의 다른 유효 소속이 없는 경우 해당 조직 이용권과 조직 범위 승인 위임을 함께 회수한다. 다른 조직 관계와 업무 이력은 보존한다. 주 소속 종료 시 남은 유효 소속 중 먼저 생성된 소속을 주 소속으로 지정한다. 예약 소속 취소는 예정 기간을 보존하고 비활성화한다. 기존 플랫폼 전체 이용권은 별도 범위이므로 자동 회수하지 않으며, 퇴사 시 계정 중지와 전체 이용권 검토가 필요하다.
4. 계정 일시 중지는 기존 관계를 삭제하지 않고 인증·세션을 차단한다. 재활성화는 명시적으로 회수/종료된 관계를 복원하지 않는다. 퇴사 관계 종료는 소속·이용권·위임 프로그램에서 처리한다.
5. 서비스 이용권은 유효 소속과 활성 계정/참여 상태를 전제로 한다. 신규 직접 부여도 승인 부여와 같은 유효성 조건을 사용한다. viewer/user/manager 범위를 유지한다.
6. 조직 권한은 해당 조직의 유효 구성원에 직접 적용하고 상위 조직 상속을 추가하지 않는다. 공통 action 권한 예외는 기존 revoke 우선 규칙을 유지한다. system.override의 우회 부여/차단 경로를 일반 예외 편집으로 열지 않는다.
7. 조직/사용자/권한 중지는 모든 변경 API에서 동일 조건을 검사한다. 마지막 유효 관리자 보호·중복 처리·오래된 상태의 변경 충돌을 검증한다.
8. 변경 이력은 구현과 함께 연결한다. 본인/관리자/승인자의 데이터 변경 조건을 공유하고 변경 후 저장 상태와 유효 접근 결과를 함께 확인한다.

### 공통 권한·진단·위임 실제 검증과 이력 확장

- `api-common-permissions.json`: 실제 API 44건 통과. 공통 범위/비관리자 차단, 조직 권한 상속 없음, 동시 부여 1건만 성공, 사용자 차단 우선·만료·회수, 오래된 변경 거절, 5앱 접근 진단, 위임 기간·회수 후 승인 거절을 검증했다.
- 브라우저: 조직 권한 재부여·기간 변경, 사용자 차단 예외 추가·회수, 위임 기간 변경·회수·회수 기록 표시 확인. 모바일 예외 입력창과 데스크톱 저장 결과 캡처를 보존했다. 이번 브라우저 기록은 관련 API 81건 성공, 오류·실패 요청 0건이었다 (`browser-common-operations.json`).
- 권한 소비 범위 주의: 현재 `common.user.manage`는 공통 권한 계산·조회에 반영되지만 사용자 관리 API/UI는 별도의 관리자 경계를 사용한다. 이 권한 부여만으로 비관리자에게 Admin 사용자 관리가 위임되는 것으로 기록하지 않는다. 프로그램별 실제 권한 소비 검토가 남아 있다.
- 공통 이력 API `/access/ops/history`: 기존 19종 history 테이블의 허용 필드만 조회. 비밀번호·토큰·복구 코드·암호화 자격증명·메일 본문을 반환하지 않는다. 필터 값은 바인딩하고 테이블/열은 정적 목록으로 제한한다.
- 기존 감사 최신 100건 조회를 유지하고 기간·대상·운영자·결과별 조회와 직전 기록 비교를 추가했다. 소속·이용권·공통 권한·승인 위임의 각 행에서 같은 이력 조회를 연다. 실제 로컬 반영·브라우저 검증 전이며 완료로 판단하지 않는다.

- 화면에서 검증 사용자 16을 A팀→B팀으로 이동하고 A팀 소속 종료·B팀 주 소속 생성 및 DMS 이용권 회수를 확인했다. 진단은 DMS 불가로 바뀌었고, 해당 사용자로 DMS에 새 로그인하면 실제 업무 화면 대신 이용 권한 안내와 신청 링크를 표시했다. 새 로그인 이후 API 3건 200, 관련 오류 0건 (`browser-transfer-staff.json`). 오래된 세션의 401을 포함한 최초 재방문은 이 합격 기록과 구분한다.

- 전보·종료 화면 재검증: 갱신된 관리자 세션에서 B팀→A팀 이동 후 소속 종료를 실행했다. 관련 API 23건 성공, 오류·실패 요청 0건 (`browser-transfer-end-repeat.json`). 최초 관리자 관찰 기록의 다른 열린 인증 정책 탭에서 발생한 세션 만료 401은 `browser-transfer-admin.json`에 보존했다. 검증 사용자 16은 현재 유효 소속·이용권이 없고 17은 A팀/PMS를 유지한다.

- 실제 SMTP 없이 모의 전송기로 메일 처리 계약 7개를 통과했다. 비활성 수동 실행의 무전송, 준비 확인 실패 시 대기 유지, 다른 worker가 선점한 메일의 전송 생략, 실패 기록과 실행 상태 해제 등을 포함한다 (`/tmp/ssoo-email-contract-tests.log`). 실제 SMTP 전달 성공과 구분한다.

- 이력 확장 후 플랫폼 검사 통과: 서버+5앱 빌드, 106 suites / 820 tests (`/tmp/ssoo-history-platform-guard.log`). worker 강제 종료 경고가 재발했으며 앞서 확인한 DMS native PDF/Canvas 핸들 제한과 함께 추적한다. 이후 이력의 관련 프로그램 탭 이동과 중첩 창 닫기를 소폭 보완했으므로 최신 Admin/서버 배포 빌드와 브라우저에서 다시 검증한다.

- 공통 이력 첫 실제 조회에서 로그인·세션 이력이 새로 추가되는 동안 offset 페이지에 중복이 나타났다. 실패 증거를 보존하고 서버의 조회 기준 시각을 다음 페이지에 전달하도록 보완했다. 19종 원천 조회·분류/대상/운영자/결과 필터·비관리자 차단·이전 값 비교 등은 별도 API 36건을 통과했다 (`api-history-sources.json`, 페이지 검증 제외).
- 화면에서 위임 회수 전후 사유/활성 값과 원본 위임 탭 연결을 확인했다. DB JSON의 timezone 없는 UTC 시각을 ISO로 정규화하고 화면에서 지역 시각으로 표시하도록 추가 보완했다. 이력 단위 테스트는 페이지 기준/시간대 회귀를 포함해 9건 통과했다. 최신 배포와 페이지·모바일 브라우저 재검증은 남아 있다.

### 후속 계정 보호 보완 (이력 배포 이미지에는 미포함)

- 기존 마지막 관리자 검사가 트랜잭션 밖에서 역할 이름만 세는 공백을 발견했다. 사용자 변경·중지는 Serializable 트랜잭션 안에서 운영자 권한을 다시 검사하고 변경 후 로그인 가능한 관리자가 남는지 확인하도록 작성 중이다. 계정·참여·잠금과 실제 system.override(차단 예외 우선)를 반영하며 충돌은 최대 3회 재시도한다. 보호/충돌/입력 회귀 3 suites / 20 tests와 서버 타입·lint는 통과했다. 실제 동작 검증과 다음 배포가 필요하다.

- 보완 후 Admin/서버 production build 및 서버 전체 107 suites / 829 tests 통과 (`/tmp/ssoo-history-review-build.log`, `/tmp/ssoo-history-account-server-tests.log`). 기존 native worker 종료 경고는 재발했다. 이력→위임 탭과 소속 상세의 중첩 이력→조직 관리 이동은 브라우저에서 오류 없이 확인했다 (`browser-history-nested.json`). 페이지 기준·시간대·계정 보호를 반영한 컨테이너 재검증 진행 중이다.
