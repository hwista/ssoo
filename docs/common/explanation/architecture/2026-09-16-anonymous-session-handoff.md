사용자 “좋아 진행하자”로 직전 정상 비로그인 처리안을 승인받았다. 세션 쿠키가 전혀 없을 때만 명시적인 정상 비로그인 응답을 반환한다. 로그인 성공으로 취급하지 않으며 이전 사용자/토큰을 지운다. 로그인 화면 디자인과 입력 방법, 인증된 성공 응답은 유지했다.

## 기존 업무·종료 검사

고객관리 큰/작은 화면의 필수 입력·등록·수정·확정 잠금 2/2와 문서관리 검색·권한 거절·실제 문서 열기/저장·내부/외부 링크·비소유 편집 회귀 4/4를 통과했다. 문서 검증용 자료 5건 삭제와 토큰 검증 계정 정리를 확인했다. 별도 임시 문서의 보호된 실제 다운로드도 직접 브라우저에서 200·원본 70바이트 일치로 확인했고, 같은 파일은 비로그인 시 401로 거절됐다. 추가 다운로드 문서 1건도 삭제 200으로 정리했다. 다섯 실행 웹 산출물과 검증 산출물 지문이 같고, 앱별 화면 소스·문서 도메인 소스·공용 화면 틀은 작업 전과 동일하다.

첫 고객관리 회귀는 큰 화면 통과 후 작은 화면의 입력 이름 클릭 안정화 대기에서 시간 초과했다. 실패 원본과 생성 번호를 보존하고 그 전용 영업기회 한 건을 삭제 200으로 정리했다. 제품과 검사 조건을 바꾸지 않은 같은 회귀의 최종 재실행은 2/2였다. 첫 실패를 통과 기록으로 덮어쓰지 않았다. 공용 생명주기 검사 한 번은 기본 현행 포트에서 실행되어 새 빌드 증거에서 제외했고, 격리 포트를 명시한 최종 검사로 대체했다.

완료 +1·신규 +1로 15완료/6대기 → **16완료/6대기(총 22건)**다. 승인 항목 처리율은 72.7%이며 제품 전체 구현률이나 출시 준비율이 아니다. 실제 운영 증거 **0/5**와 아래 인증 결함이 남아 있어 출시 완료로 판정하지 않는다.

## 다음 승인 대상

갱신 전 토큰 재사용 차단을 먼저 제안한다. 토큰 전체 비교·매회 고유값·원자적 교체와 다섯 서비스 동시 복원을 함께 검증한다. 기존 저장 방식의 로그인 세션은 새 방식으로 안전하게 소급 복원할 수 없어, 보수적 전환안은 기존 사용자의 한 번 재로그인을 포함한다. 사용 방식 변경의 사전 승인 원칙에 따라 [검토안](../../../../output/playwright/approval09-anonymous-session-20260916/approval22-proposal.md)만 준비했으며 제품에는 적용하지 않았다.
