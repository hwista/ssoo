# 서비스 품질 재점검

> 2026-09-18 · 사용자 지시: 테스트 배포는 이미 존재, 현재 우선순위는 서비스 품질 · 제품 변경 없음

> 2026-09-21 후속: 이 문서에서 재개했던 승인-13의 목록 글 겹침은 사용자 순차 승인 후 보완·검증 완료했다. 같은 원인의 타임라인 제목도 보완했다. [새 검증 결과](../../../../output/playwright/pms-list-fix-20260921/results.md)와 [현재 승인 대장](2026-09-11-launch-approval-register.md)을 우선한다. 아래 “수정 미적용·승인 대기”와 수치는 9월 18일 당시 기록이며, 전 서비스 시각 품질 완료를 뜻하지 않는다.

## 현재 판단

운영 서버 선정·용량·배포·복구 검증은 현재 범위에서 보류한다. 기존 승인 처리율을 서비스 전체 품질이나 구현률로 해석하지 않는다. 최근 개별 수정의 통과 기록과 이번 현재 버전 재검사를 분리한다.

**새로 재현한 제품 결함은 프로젝트 목록의 글 겹침 1건이다.** 기존 승인-13의 화면 보완으로 다시 열며 신규 승인 번호를 추가하지 않는다. 설정 저장 기능이 사라진 것은 아니지만, 기존 완료 판정의 시각 검증이 충분하지 않았다. 현재 대장은 **20완료·1보완 승인 대기·1운영 보류 / 총 22건**이다.

## 다음 순서

1. 현재 승인-13 보완안을 승인 대장에 모은다. 허용되지 않은 화면 변경을 먼저 적용하지 않는다.
2. 실행 중인 별도 빌드와 충돌하지 않는 검증 산출물을 확보한 후 문서 업무·커뮤니티 작성/첨부/댓글·공용 검색을 다시 실행한다. 테스트 배포를 재구성하거나 서버 사양을 조사하는 작업이 아니다.
3. 고객관리의 긴 표·등록 양식·저장/확정 버튼 접근성을 핵심 17화면 기준으로 다시 확인한다. 과거 기능 통과를 시각 품질 완료로 대체하지 않는다.
4. 다른 서비스의 동일한 글 겹침 후보를 정상·긴 내용·작은 화면에서 재현한다. 재현된 문제만 기존 항목 보완 또는 별도 승인 대상으로 기록한다.
5. 승인된 수정마다 저장·재조회·권한·실패 복구·서비스 간 이동과 실제 화면을 다시 확인한다.
