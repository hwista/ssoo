# 답글 원문 연결 검사 작업 결과

> 2026-09-16 · 승인-21 완료 · 총 21항목 중 15완료·6승인 대기

사용자 “진행하자”로 직전 답글 원문 일치 검사안을 승인받았다. 답글 생성 전에 원문 댓글의 게시물 번호가 작성 대상과 같은지 검사하도록 서버 조건 하나를 추가했다. 기존 원문의 존재·활성 여부 확인과 같은 거절 응답을 사용한다.

| 기능 | 실제 확인 결과 |
|---|---|
| 다른 게시물 원문 | 수정 전 비공개 원문 조회는 거절되지만 다른 공개 게시물에 연결 저장되는 문제 재현. 수정 후 다른 공개/비공개 원문 모두 거절 |
| 비활성·없는 원문 | 기존 거절 유지. 네 종류 잘못된 원문 요청의 실제 저장 0건 |
| 정상 댓글·답글 | 일반 댓글·같은 게시물 답글·다단 답글 3건 정상 저장, 깊이 0·1·2 유지 |
| 기존 댓글 화면 | 큰/작은 화면에서 원문 관계·긴 답글·원문 없는 답글·초안 보존, 일반 댓글 1건 등록·댓글 수·새로고침 통과 |
| 공개 범위 | 일반 작성 계정의 비공개 게시물 댓글 조회·작성 거절 유지 |
| 기존 업무 | 고객관리 2/2·문서관리 4/4 회귀 통과 |

관련 서버 검사 3묶음 16/16과 새 서버 빌드(의존 작업 포함 3/3·캐시 0)가 통과했다. 잘못된 연결은 기존 찾을 수 없음 응답으로 거절하고 원문 본문·비공개 여부를 노출하지 않는다. 정상 요청/응답 형식·알림과 기존 권한 검사를 보존했다.

제품 수정은 서버의 답글 생성 조건과 재발 검사에 한정한다. 다섯 웹 앱·공용 패키지·문서관리 코드는 변경하지 않았으며 다섯 웹 빌드도 그대로 사용했다. 새 답글 작성 화면이나 기존 자료 보정 작업을 구현한 것은 아니다. 구조·불필요 변경 검토는 같은 에이전트의 직접 검토다.

서버 재시작 완료 전에 브라우저가 먼저 열린 한 실행에서 연결 거절과 세션 중계 오류가 발생했다. 이를 정상 검증으로 세지 않고 원본을 보존했다. 서버 기동 후 새 페이지 진입·로그인과 최종 댓글 검사에서는 관련 요청·콘솔·실행 오류 0을 확인했다. 로그인 전 세션 없음 401은 기존 승인-09로 별도 유지한다.

수정 전 재현 자료와 정상 생성 자료를 모두 정리했고 시작 전 건수·기존 게시판 원문을 대조했다. 문서 회귀의 생성 자료 삭제 응답 5건도 확인했다. 감사 이력·번호 시퀀스까지 되돌렸다는 의미는 아니다. [실행 증거](../../../../output/playwright/approval21-reply-parent-20260916/results.md)에 소스/빌드 대조를 함께 기록했다.

완료 +1·신규 0으로 **총 21항목 중 15완료·6승인 대기**다. 운영 증거 0/5는 여전히 미완료이며 승인 처리율을 출시 준비율로 해석하지 않는다.

다음은 기존 승인-09 **로그인 전 세션 확인**이다. 세션이 전혀 없는 정상 비로그인을 명시적으로 처리하면서 만료·위조·철회·통신 장애와 보호된 업무 거절을 유지하는 [수정안](../../../../output/playwright/approval21-reply-parent-20260916/approval09-proposal.md)을 준비했다. 공용 응답 계약 변경이므로 아직 적용하지 않았다.
