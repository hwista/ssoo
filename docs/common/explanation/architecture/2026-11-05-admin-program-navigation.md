# Admin 공통 관리 프로그램 배치와 사용성 검증

> 2026-11-05 · 상태: 기존 로컬 배포·Ralph 검증 완료

## 문제와 변경 범위

17개 공통 관리 프로그램을 기존 메뉴의 상세 창·탭에 넣은 결과, 소속·계정 복구·권한·감사 기능을 운영자가 메뉴에서 발견하기 어려웠다. 메뉴 이름만 검색하므로 전보·잠금·메일 수신함 같은 실제 작업으로 찾을 수도 없었다. 사용자의 재배치 지시에 따라 Admin의 탐색 구조를 변경한다. 앱 도메인 관리·서버의 권한 및 변경 규칙은 이 작업에서 변경하지 않는다.

## 관리 대상별 배치

| 묶음 | 프로그램과 주 진입 주소 |
| --- | --- |
| 조직·사용자 | ADM-01 회사·조직 `/organizations`, ADM-02 사용자 `/users`, ADM-03 소속 `/memberships`, ADM-04 계정 상태·복구 `/accounts` |
| 이용·권한 | ADM-05 애플리케이션 기준 `/applications`, ADM-06 서비스 이용권 `/service-grants`, ADM-07 역할·기능 권한 `/roles`, ADM-08 조직 공통 권한 `/organization-permissions`, ADM-09 사용자 권한 예외 `/user-permissions`, ADM-10 유효 권한 진단 `/access-diagnosis`, ADM-11 승인 담당자·위임 `/approval-authorities` |
| 신청·이력 | ADM-12 공통 신청 처리 `/approvals`, ADM-16 공통 변경 이력 `/operation-history` |
| 시스템 운영 | ADM-13 공통코드 `/codes`, ADM-14 인증 정책 `/auth`, ADM-15 인증 메일 운영 `/email-operations`, ADM-17 AI 실행 운영 `/ai-operations` |

메뉴 그룹은 기본으로 펼쳐져 있고 검색 중에는 일치 그룹이 열린다. 본인 소속·서비스 신청은 ‘내 업무’에 별도로 둔다. 일반 사용자에게 관리자 메뉴를 노출하지 않으며, 위임 승인자는 공통 신청 처리에만 추가 진입한다. 대시보드는 같은 메뉴 정의의 기능 설명과 진입 링크를 보여준다. 데이터를 편집하는 기능을 대시보드에 복제하지 않는다.

기존 소속·이용권·권한·이력 패널을 주 화면과 사용자/조직 상세에서 공유한다. 계정 운영도 동일 사용자 목록·처리 코드를 사용하고 주요 작업 이름을 버튼에 표시한다. 역할별 기능 명세, 기존 예외 내역, 최근 감사 이벤트는 각각 관련 프로그램 안에서 유지한다. 기존 `/roles?tab=...` 링크는 새 프로그램 경로로 해석하고 검색 등 나머지 query는 보존한다. 인증 정책에서 분리한 메일·가입 신청은 이름 있는 연결 버튼으로 이어진다.

## 완료 조건과 Ralph 검증

1. 관리자 메뉴에 17개 프로그램이 이름으로 노출되고 각 항목 선택 시 해당 관리 기능이 열린다. 주소 직접 진입/새로고침도 가능해야 한다.
2. ‘전보’, ‘잠금’, ‘SMTP’, ‘감사’로 적절한 메뉴가 검색되고 그룹 접힘 때문에 결과가 숨지 않는다. 검색 해제 시 전체 메뉴가 복원된다.
3. 사용자·조직의 소속/이용권/이력 연결, 역할 영향 사용자→진단, 변경 이력→원본, 인증 정책→메일/가입 신청을 실제 조작한다. 변경 폼·실패 안내·재시도를 유지한다.
4. 데스크톱 1440×1000, 모바일 390×844에서 메뉴와 대상 화면을 확인한다. 모바일 선택 후 메뉴가 닫히고 주요 기능을 가리지 않아야 한다.
5. 일반 사용자/위임 승인자의 메뉴 경계를 유지한다. 탭 용량 초과를 무반응으로 처리하지 않고 열린 작업을 보존한 채 닫기 안내를 제공한다.
6. 관련 HTTP/proxy/console/runtime 실패를 수집한다. 의도된 장애 주입은 정상 경로와 분리하고 복구까지 확인한다.
7. 정적 회귀, lint/타입, preflight, 서버+5앱 platform guard, 관리형 기존 포트 배포를 통과한 뒤 실제 배포본을 검증한다. 검증 뒤 아키텍처/중복·불필요 UI를 재검토하고 변경 시 관련 검증을 다시 실행한다.

정적 회귀: `node scripts/verify-admin-program-navigation.mjs`. 브라우저 증거: `output/playwright/admin-navigation-20261105/`. 실행 전 메뉴 기준 화면을 `before.png`로 보관했다. 구현 완료와 운영 전체 시나리오 보장은 구별한다.

## 최종 검증 결과

- 기존 Admin 3000 컨테이너에 반영했고 healthy 및 관리형 storage guard를 통과했다. 서버·다른 앱·DB를 재배포하지 않았다.
- 관리자 메뉴 17개 각각 선택→해당 제목/관리 화면을 확인했다. 17개 주소의 직접 접속도 통과했다. 최초 브라우저 검사에서 새 주소의 middleware 허용 목록 누락으로 404를 발견해 수정하고 재배포했다. `verify-admin-program-navigation.mjs`는 실제 경로 정책 함수로 이 누락을 재검사한다.
- 전보·잠금·SMTP·감사 검색, 접힌 그룹 검색, 결과 없음, 검색 해제 및 키보드 선택을 통과했다.
- 모바일 390×844에서 검색→소속 화면→새로고침→배치 폼, 이용권 부여 폼, 문자 버튼→계정 운영, 조직→같은 조직의 이용권, 이력 상세→원본 프로그램, 인증 정책→메일·수신함/가입 신청, 역할 영향 사용자→선택 사용자 진단을 확인했다. 폼은 열기·취소 검증이며 실제 관계를 새로 쓰거나 기존 정보를 변경하지 않았다.
- 소속 조회 503을 통제 주입하여 오류 안내·쓰기 차단을 확인하고, 장애 해제→재시도→배치 폼 복구까지 통과했다. 일반 사용자/위임 승인자는 **통제된 onboarding 응답으로 UI 메뉴·화면 경계**를 검증했다. 이를 실제 비관리자 토큰의 서버 권한 검증으로 확대하지 않는다.
- 16개 탭 제한 도달 시 안내 표시·열린 작업 보존·1개 닫은 뒤 새 기능 열기, 과거 권한 진단 사용자 ID/감사 링크 호환을 실제 브라우저에서 확인했다.
- 최종 브라우저 기록의 예상하지 않은 HTTP·console/runtime 실패는 0건이다. 주입한 503와 대응 console 4건, 페이지 이동으로 취소된 요청은 별도 기록했다. 초기 404 실패와 검증 도구의 locator/호버 수정 기록도 보존했다.
- 코드 구조 검토: 17개 메뉴의 정의를 사이드바·대시보드·탭 이름에서 공유한다. 소속·이용권·권한·계정·이력의 처리 구현을 복제하지 않았다. 메일 작업은 기존 인증 정책 파일에서 옮겼으며 설정/전송/재시도 경로를 유지했다. 공개 권한 확대나 도메인 관리 편입은 없다. 메뉴 재배치 후 불필요한 이중 색인과 중복 내부 탭을 정리했고, 변경한 화면과 복구 동선을 최종 배포본에서 다시 검증했다.
- preflight, 경로/탭 회귀, UI consumption/input intent/frame, lint(오류 0), 서버+5앱 platform guard와 최종 Docker 빌드를 통과했다. 서버 테스트는 변경 없는 기존 114 suites/872 tests 캐시 결과이며, 실제 브라우저와 신규 경로 회귀는 이번 실행 결과다.

주요 증거: `navigation-final.txt`(17개 메뉴/주소/검색), `mobile-final.txt`(모바일 동선), `roles-final.txt`(오류 복구/통제 역할), `tabs-final.txt`(용량·기존 링크), `verification.txt`(최종 통합 기록), `dashboard-desktop.png`, `menu-mobile.png`, `membership-form-mobile.png`, `account-recovery-mobile.png`, `mail-mobile.png`. 경로는 모두 `output/playwright/admin-navigation-20261105/` 아래다. 전체 15개 운영 시나리오의 무제한 보장이나 외부 유료 연동 성공을 선언하는 결과가 아니다.
