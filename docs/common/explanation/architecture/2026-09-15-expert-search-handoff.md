# 커뮤니티 전문가 검색 작업 결과

> 2026-09-15 · 승인-02 완료 당시 기록 · 당시 총 19항목 중 10완료·9승인 대기

후속 승인-19는 [공용 프로필 핸드오프](2026-09-15-profile-state-handoff.md)에서 완료했다. 아래 신규 발견·미적용 서술은 전문가 검색 완료 당시의 기록이다.

직전 변경안에 대한 사용자 ‘다음 진행’으로 전문가 검색 연결을 승인받았다. 검색 입력과 분류만 있고 결과를 조회하지 않던 화면에 실제 사용자 조회를 연결했다.

| 기능 | 확인 상태 |
|---|---|
| 이름·표시 이름·소개·기술 검색 | 실제 조회 확인 |
| 여섯 기술 분류 | 검색어와 조합해 실제 보유 기술 필터 적용 |
| 검색 결과·페이지 이동 | 사진·이름·제공되는 부서·기술 표시, 20명/1명 경계와 이전/다음 확인 |
| 결과 선택 | 기존 공용 프로필로 이동 |
| 로딩·결과 없음·조회 실패 | 상태 구분, 입력 보존과 실제 재시도 확인 |
| 열람 권한·사용자 전환 | 권한 없는 실제 계정의 검색 거절, 다음 계정의 검색 상태 초기화 확인 |
| 큰/작은 화면 | 1440·390px 실제 브라우저 확인, 정상 검색 흐름 오류 0 |

검색 조건/게시물 관련 서버 검사 9/9, 실제 데이터 조회 검사 10/10, 실제 요청·권한 검사 6/6을 통과했다. 브라우저는 정상 흐름 11묶음과 실패 복구/계정 전환 3묶음을 확인했다. 이 숫자는 서로 다른 검증 종류이며 합산하여 서비스 완료율로 표시하지 않는다. 기존 패널 4/4·문서 업무 4/4까지 최종 회귀도 통과했다. 검증용 사용자·프로필·기술은 원래 건수로 복원하고 문서 5건의 삭제 성공을 확인했다. 상세 결과는 [실행 증거](../../../../output/playwright/approval02-expert-search-20260915/results.md)를 따른다.

서버 새 빌드는 의존 작업 포함 3/3, 커뮤니티 새 빌드는 5/5·캐시 0으로 통과했다. 첫 웹 빌드의 사용자 식별자 타입 오류, 검증 빌드의 서버 주소 누락, 기동 직후 연결 거절은 원본을 보존하고 수정 후 재검증했다. 글꼴 없는 초기 캡처와 화면 크기 전환 중간 캡처도 최종 시각 증거에서 제외했다.

## 승인 경계와 새 발견

기존 검색 응답 필드와 권한 가드를 유지하고 이름 조건·사용자 표시 정보만 보완했다. 공용 프로필, DMS 화면·문서 업무·연동 계약, 공용 인증/화면, 게시판·게시물의 제품 구현은 변경하지 않았다. 세부 계약은 [전문가 검색 설명](../../../sns/explanation/architecture/expert-search.md)을 따른다.

새로 확인한 **공용 프로필의 비활성 자료 표시**는 승인-19로 별도 등록한다. 검색은 비활성 프로필/기술을 제외하지만 기존 프로필 직접 주소와 소개 영역에서는 표시됨을 재현했다. [재현 및 변경안](../../../../output/playwright/approval02-expert-search-20260915/approval19-proposal.md)을 준비했으며 임의로 변경하지 않았다. 다음은 이 문제를 먼저 처리하도록 제안한다. 기존 게시판 생성(승인-03)도 대기 상태다.

이번에는 **완료 +1·신규 승인 항목 +1**이다. 완료는 **9→10건**, 총 항목은 **18→19건**, 대기는 **9→9건**이다. 새 발견을 계속 기록하면서 완료 실적과 구분한다. 승인 처리 비율 **10/19(52.6%)**은 출시 준비율이 아니다.

## 검증 범위의 한계

검증은 격리 데이터베이스와 검증용 웹/서버에서 수행했다. 운영 배포는 하지 않았고 실제 운영 증거 0/5는 남아 있다. 공용 프로필 비활성 문제를 검색 완료에 포함하지 않는다. 구조·불필요 변경 검토는 동일 에이전트가 수행했으며 독립 검토자 승인으로 표시하지 않는다.
