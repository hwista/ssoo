# 상단 검색 배치 승인 적용 핸드오프

> 작성: 2026-09-22 · 상태: 승인 범위 적용·검증 완료

## 승인과 적용 범위

사용자는 다섯 서비스의 좁은 데스크톱 검색란을 별도 줄로 배치하고 프로젝트관리의 데스크톱 중복 제목을 정리하는 미리보기를 확인한 뒤 “좋아 진행”으로 승인했다. 문서관리 상단의 시각 변경을 명시적으로 포함한다. 로그인 옵션 통일·검색 결과 문구·설정 내부 배치는 이 승인에 포함하지 않는다.

768~1023px에서는 상단 104px의 두 줄 배치, 1024px 이상에서는 기존 60px 한 줄 배치를 사용한다. 768px·사이드바 펼침 상태의 검색 폭은 다섯 서비스 모두 396px다. 모바일·검색 없는 설정 상단은 60px를 유지한다. 프로젝트관리 모바일 제목과 기존 탭·본문 제목도 유지한다. 검색 계약과 업무·문서 저장 동작은 변경하지 않았다.

늘어난 높이에서 알림창이 검색란을 덮지 않도록 실제 header 하단 위치를 관측해 panel 위치를 갱신한다. 공용 header/알림 surface와 프로젝트관리의 header 주입만 변경했으며 앱별 화면 복제나 새로운 검색 경로를 도입하지 않았다.

## 검증 결과

[검증 상세 및 제한](../../../../output/playwright/header-layout-20260922/results.md)과 [실제 적용 화면](../../../../output/playwright/header-layout-20260922/screens.html)을 참조한다.

- 현재 소스의 다섯 웹 앱 새 빌드 5/5.
- 서비스별 9개 화면 폭, 총 45개 상단 상태. 데스크톱 크기 전환의 입력 유지 30/30.
- 실제 검색 응답·결과 진입 5/5. 문서관리 검색 후 입력 비우기 보존.
- 알림창 위치의 화면 크기 전환 15/15. 사용자 메뉴·키보드 이동·입력 지우기 확인.
- 다섯 서비스의 사이드바·모바일 메뉴·새 항목 등록 진입 확인. 실제 신규 저장은 시험 범위가 아니다.
- 문서관리 설정 상단 보존 3/3. 설정 내부 배치 전체의 정상 판정은 아니다.
- 최종 관련 브라우저 요청·실행 오류 0건. 사전/규칙/문서관리 보호 검사와 변경 범위의 코드·문서 검증 통과.

기존 배포를 교체하지 않고 별도 검증 포트를 사용했다. 초기 임시 실행 환경 및 검증 선택자 실패는 기록을 보존한 후 해결·재검증했으며 최종 통과 수치에 섞지 않았다. 빌드 입력과 현재 웹·공용 소스의 해시가 일치한다.

## 잔여와 다음 순서

이번 상단 배치 승인 범위는 완료·승인 대기 0건이다. 로그인 기능 구성과 검색 결과의 업무용 표현은 후속 검토로 남는다. 좁은 문서관리 설정에서 항목명 쪼개짐·입력란 겹침이 확인됐으며 기존 설정 품질 잔여의 증거로 보관했다. 사용자 사진의 옅은 검색 배경은 원인 미확정 상태다. 후속 화면 변경은 구체안을 제시하고 별도 승인을 받는다.

기존 정식 승인 22항목의 21완료·1운영 보류와 번호는 유지한다. 이 결과는 상단 검색 배치의 완료이며 전체 서비스 품질이나 운영 출시 준비의 완료가 아니다.
