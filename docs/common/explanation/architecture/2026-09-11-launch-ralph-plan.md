## 변경 권한

- DMS는 사용자 품질 검수가 끝난 기준선이다. 화면, 사용 방법, API 계약을 임의로 변경하지 않는다.
- 모든 서비스의 사용 환경·사용 방법·시각 요소 변경은 사전 사용자 승인 대상이다. 공용 화면 구성요소의 변경도 동일하다.
- CRM만 명백히 정리되지 않은 화면을 먼저 정리하고 결과를 보여줄 수 있다. 기존 기능, 입력 항목, 업무 순서, 기본값, 권한, API 계약을 보존하는 범위에 한한다. 기능 추가·제거·흡수·대체는 예외에 포함되지 않는다.
- 승인 대상은 [별도 승인 대장](2026-09-11-launch-approval-register.md)에 누적한다. 다섯 단계의 승인 범위 내 작업을 먼저 수행한 뒤 하나씩 검토한다. 보류를 완료로 집계하지 않는다.
- 기존 로컬 실행 환경 복구와 격리된 검증 환경 생성은 이번 검증 범위다. 운영 배포·사용자 데이터 변경·원격 게시를 의미하지 않는다.

## 검증 원칙

검사 유지보수도 제품 변경과 구분한다. DMS의 기존 루트 홈 복귀·문서 탭 선택·공용 검색 동작에 맞춰 오래된 브라우저 검사 세 파일의 대상과 검증 주소를 보정한다. 숨겨진 본문을 통과로 인정하거나 기능·권한·저장 검사를 제거하지 않으며, DMS 제품 화면과 API는 변경하지 않는다. 검사 코드 변경 전 증거는 보존했고, 변경 후 동일 작업본으로 통합 검증과 문서관리 검사를 다시 수행했다.

1. 소스·문서의 주장과 브라우저 재현 결과를 구분한다. 과거 통과를 현재 통과로 재사용하지 않는다.
2. 정상·빈 상태·오류와 재시도·유효성 검사·권한·잠금·대화상자·긴 데이터를 화면별로 추적한다. 크기는 1440×1000, 1366×768, 390×844를 기준으로 한다.
3. 업무 데이터 변경이 필요한 검증은 별도 데이터베이스와 별도 문서 저장소를 사용하는 기존 격리 실행 도구로 수행한다.
4. 오류 재현 → 최소 수정 → 관련 검사 → 실제 브라우저 → 구조·불필요 변경 검토 → 영향 있는 회귀 확인 순으로 반복한다.
5. 브라우저의 관련 요청 실패·실행 오류·콘솔 오류가 남으면 해당 검증은 실패다. 기존 미구현 기능을 완료로 집계하지 않는다.
6. 비율은 분모가 고정된 검증에만 사용한다. 화면 감사율, 결함 해결률, 출시 필수 증거 충족률을 구현률과 혼합하지 않는다.
