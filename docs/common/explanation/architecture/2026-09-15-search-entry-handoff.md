사용자 “발견한 건 처리하는게 맞지. 그 다음 진행하자”로 승인받은 검색 직접 접속·새로고침 복원안을 적용했다. 새로 발견한 문제도 계속 대장에 등록하되 완료 건수와 추가 발견 건수를 구분한다.

## 화면별 확인 결과

| 화면·동작 | 확인 결과 |
|---|---|
| 프로젝트·문서관리 검색 주소 직접 접속 | 빈 화면 대신 기존 검색 화면·탭·결과 표시 |
| 로그인 후 복귀 | 처음 요청한 검색 주소·검색어·서비스 필터로 복귀 |

프로젝트 저장 탭은 소유 사용자를 함께 기록한다. 동일 사용자 복원과 다른 소유자·출처 없는 저장 자료·로그아웃 정리를 구분한다. 이전 버전처럼 소유자가 없는 저장 탭은 처음 사용자 확인 때 정리하며, 사용자 확인을 거치기 전 검색 화면을 노출하지 않는다. 미저장 업무 입력을 새로고침 후 저장·복구하는 기능을 추가한 것은 아니다.

## 변경과 보존 경계

두 검색 진입점에서 기존 앱 화면 틀을 연결했다. 프로젝트의 사용자별 탭 보존과 검색 경로 갱신을 보완했고, 두 서비스의 직접 검색 주소에서만 재검색·필터 선택을 주소에 반영한다. 문서관리는 직접 검색 주소의 빈 검색 상태로 전환할 때 이전 검색 결과를 초기화한다. 기존 루트에서 빈 상단 검색을 제출할 때는 기존 결과를 유지한다.

공용 화면·공용 인증 구현·서버·요청/응답 계약·권한 정책·문서 본문·편집/저장·설정 진입점·미들웨어·다른 세 앱 제품 소스는 수정하지 않았다. 기존 탭 한도나 자동 닫기 규칙도 바꾸지 않았다. 문서관리 품질 검수 기준을 이번 승인 외의 화면 변경 권한으로 확대하지 않았다.

## 검증 상태와 실패 기록

- 프로젝트 새 빌드는 의존 작업 포함 **5/5, 캐시 0**으로 통과했다. 문서관리도 보존 검사·새 빌드를 통과했고 반복 갱신 보정 뒤 다시 검사·빌드했다.
- 두 서비스의 직접 접속·로그인 복귀·검색어/필터·방문 기록 회귀 **4/4 통과**. 프로젝트 소유자 보호도 순차 재검증으로 통과해 새 검색/소유자 회귀는 총 5/5다. 동시 실행 당시 요청 제한 실패는 별도 보존했다.
- 실제 브라우저는 두 서비스 각각 **1920·1440·390px**에서 직접 접속·새로고침·방문 기록·필터 복원·빈 검색 주소를 확인했다. 최종 직접 검증의 정상 검색 흐름 요청·콘솔·실행 오류는 **0건**이었다. 기존 루트 검색 동선도 확인했다.
- 기존 검색 패널 4/4·고객관리 7/7·문서관리 관련 업무 4/4까지 최종 관련 회귀 **20/20**을 확인했다. 검사별 집계는 [실행 결과](../../../../output/playwright/approval18-search-entry-20260914/results.md)를 따른다. 이는 이번 변경과 관련된 회귀 범위이며 서비스 전체 기능 완료율이 아니다. 문서관리 검색 권한·승인/거절/철회·내부/외부 문서 열기·편집 권한자 저장을 확인하고 격리 문서 다섯 건의 삭제 성공도 확인했다.

첫 문서관리 검사 2건은 이번 주소 동기화 구현의 반복 갱신 오류로 실패했다. 자동 검색 완료와 사용자 검색 변경을 구분하고 동일 경로 갱신을 생략한 뒤 새 빌드에서 두 건 모두 통과했다. 이를 새 승인 항목으로 추가하지 않았다.

기존 인증 정적 검사는 무조건 탭 정리를 요구해 실패했다. 소유자 기준 위임·접근 상태 초기화·같은 사용자 보존·로그아웃/다른 소유자 정리를 검사하도록 갱신하고 실제 브라우저 검사를 함께 수행했다. 해당 검사도 통과했다는 앞선 진행 안내는 사용자에게 정정했다.

CLI 로그인 가정·크기 전환 직후 입력 대기 중단 및 동시 검사에서 세션 복원 요청 제한으로 로그인 화면에 돌아온 실패도 원본으로 보존했다. 제품의 요청 제한이나 오류 단언을 완화하지 않았으며 묶음 간 간격을 둔 순차 실행으로 통과했다. 직접 검색 주소의 빈 안내와 기존 루트의 빈 입력 결과 유지는 별도 단언으로 검증했다. [증거와 실패 분류](../../../../output/playwright/approval18-search-entry-20260914/results.md)를 통과 기록과 함께 본다.

빈 상태 초기화는 직접 검색 주소에만 적용한다. 패널 회귀에서 루트의 기존 빈 입력 동작까지 바뀔 수 있음을 확인해 보정한 뒤 문서관리 보존 검사·새 빌드·브라우저·관련 회귀를 다시 수행했다.

## 실행물과 다음 작업

프로젝트와 문서관리 검증 웹만 새 빌드로 교체했다. 다른 세 웹과 격리 서버 실행물은 그대로다. 문서관리 요청이 전용 검증 데이터베이스를 사용하는 서버로 연결됨을 다시 확인했다. 실제 운영 배포는 하지 않았으며 **실제 운영 증거 0/5**는 남아 있다.

구조·불필요 변경 검토는 동일 에이전트가 수행했다. 독립 검토자 승인으로 표시하지 않는다. 빌드 후 보정 범위와 최종 제품/실행물은 [최종 대조](../../../../output/playwright/approval18-search-entry-20260914/final-reconciliation.json)에 기록한다.

이번에는 **완료 +1·새 승인 항목 0**, 대기 **10→9건**이다. 전체 승인 대장은 **9/18 완료(50%)·9대기**이며 출시 준비율을 뜻하지 않는다. 새 발견은 계속 등록하고 이 두 수치를 구분한다.

다음 제안은 기존 대기 항목인 **승인-02 커뮤니티 전문가 검색**이다. 입력과 결과 조회가 연결되지 않은 화면을 기존 조회 기능에 연결하고 이름·기술 검색, 분류, 실제 결과와 프로필 이동을 완성하는 [검토안](../../../../output/playwright/approval18-search-entry-20260914/next-approval-proposal.md)을 준비했다. 별도 사용자 승인 전에는 적용하지 않는다.
