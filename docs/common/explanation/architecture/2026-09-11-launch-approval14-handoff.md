창을 크게 하거나 작게 만들 때 입력과 열린 창이 사라지던 세 화면을 수정했다. 새 실행본의 실제 브라우저에서 확인한 범위는 다음과 같다.

| 관리·사용자 추가 | 추가 창과 입력 유지, 전환 후 등록·재조회, 취소 후 새 입력 | 통과 |

## 검증 수치

- 수정 전 세 화면 양방향 **6건 모두 입력 또는 열린 창 소실**을 재현했다.
- 수정 후 같은 여섯 출발 조건에서 반복 전환 **24/24회** 입력·창 유지. 별도 메뉴 닫기 9건과 서비스별 접기·펼치기, 취소 확인도 통과했다.
- 크기 전환 후 실제 등록·재조회 **6/6건** 통과. 영업기회의 기존 필수 입력·수정·확정 잠금 회귀도 **2/2건** 통과했다.
- 문서관리·커뮤니티 대표 초안 **4/4건** 유지. 검증한 미저장 입력 흐름에서 자동 저장 **0건**.
- 조회 전용 계정의 등록 거절 **3/3건**과 관리 접근 제한 화면의 크기 전환 유지 확인. 프로젝트는 조회 전용 계정의 홈에서 태스크 추가가 노출되지 않음을 확인했으며, 모든 프로젝트 역할 조합 검증으로 확대하지 않는다.
- 다섯 웹 서비스·서버의 새 빌드 **11/11작업, 빌드 캐시 0건**, 사전 검사·코드 검사·문서 검사·규칙 동기화·실행 화면 구조 검사 통과.
- 최종 정상 업무 흐름의 관련 통신·실행 오류 **0건**. 로그인 전 세션 거절과 권한 검사에서 의도한 거절 응답은 별도로 기록했다.

각 숫자의 분모가 다르므로 합산하여 전체 기능 완료율로 쓰지 않는다.

## 보존한 범위와 남은 문제

본문을 감싸는 틀을 유지하도록 보정했다. 화면 배치·항목·메뉴·필수 조건·저장 방식·권한은 유지했다. 문서관리와 커뮤니티 제품 코드는 이번 작업에서 변경하지 않았다.

영업기회 등록·조회 탭을 함께 열 때 기존 입력 이름 연결이 중복되는 문제는 **승인-11로 남아 있다**. 등록 탭의 고객명에 이름이 두 번 연결되고 다른 탭의 입력에는 연결되지 않는 재현 증거를 추가했다. 이번 최종 등록 검증은 크기별로 검증용 탭 상태를 초기화한 독립 화면에서 실행했으며, 모든 탭 조합의 정상 동작을 보장하지 않는다. 다음 제안은 이 입력 이름 연결 부분의 보정이다. 열린 탭 한도 문제는 별도 구체안을 마련해야 한다.

실제 운영 배포는 하지 않았다. 기존 사용 환경의 실행 서비스를 교체하지 않았고 전용 데이터베이스에서만 등록을 검증했다. 재시도에서 만든 자료까지 포함해 활성 검증 항목은 0건이며, 검증 계정 두 개는 비활성화했다. 실제 운영 출시 증거는 **0/5**로 남는다.
